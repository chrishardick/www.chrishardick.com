PTHREADS: CONDITION VARIABLES


  • Condition Variables are used for communicating state information of data shared betweeen threads
  • I.e. item arrived on a queue, queue is empty, etc.
  • Each condition variable is associated with a mutex


1. CONDITION VARIABLE DATATYPE: PTHREAD_COND_T

    #include <pthread.h>

pthread_cond_t my_cond;
  • an opaque type -- (see Opaque Datatypes)
  • never copy a condition variable - the result is undefined (it's opaque)
  • if you need access to a condition variable, you can copy a pointer to a condition variable (into a function, etc.)


2. CONDITION VARIABLE CREATION & DESTRUCTION

  • In order to use a condition variable, it must first be initialized (and initialized only once)
  • There are two ways a condition variable can be initialized
    1. static initialization
    2. dynamic initialization

A. STATIC INITIALIZATION

    /*
 * statically initialize a condition variable using PTHREAD_COND_INITIALIZER macro
 */
pthread_mutex_t StaticMutex = PTHREAD_MUTEX_INITIALIZER;
  • statically initializes a condition variable with default attributes.
  • if you need to specify attributes, you must use dynamic initialization
  • if you dynamically allocate a condition variable, you must use dynamic initialization
  • condition variables which are initialized statically do NOT need to be destroyed

B. DYNAMIC INITIALIZATION

    /*
 * dynamically initialize a condition variable
 *
 * RETURN
 * ======
 * 0 = success
 * else - see discussion on pthreads and errors
 */
int pthread_cond_init (pthread_cond_t* p_Cond,                // in
                       pthread_mutexattr_t* p_CondAttr);      // in: pass NULL for default attributes
  • condition variables which are dynamically initialized need to be destroyed using pthread_mutex_destroy()
  • you can safely destroy a condition variable which has no thread(s) blocked on it & no additional thread(s) will try to wait on, signal, or broadcast the condition variable
  • how do you know if no threads are blocked on the condition variable & that no threads will try to use it in the future? You have to have a solid grasp of the program logic!!! 
    /*
 * destroy a dynamically initialized condition variable
 *
 * RETURN
 * ======
 * 0 = success
 * else - see discussion on pthreads and errors
 */
int pthread_cond_destroy (pthread_cond_t* p_Cond);           // in

    /*
 * an example
 */

#include <pthread.h>
#include <string.h>      // for strerror_r()

char szEMsg[80];

pthread_cond_t* p_DynamicCond = (pthread_cond_t*) malloc (sizeof(pthread_cond_t));

int iRC = pthread_cond_init (p_DynamicCond, NULL);

if (iRC != 0)
{
	strerror_r(iRC, szEMsg, sizeof(szEMsg));

	cout << "ERR: UNABLE TO INIT DYNAMIC CONDITION VAR: " << szEMsg << endl;
	
	return false;
}

...

iRC = pthread_cond_destroy (p_DynamicCond);

if (iRC != 0)
{
	strerror_r(iRC, szEMsg, sizeof(szEMsg));

	cout << "ERR: UNABLE TO DESTROY DYNAMIC CONDITION VAR: " << szEMsg << endl;
	
	return false;
}


3. WAITING ON A CONDITION VARIABLE

  • Use pthread_cond_wait( ) & pthread_cond_timedwait( ) to wait on a condition variable
  • In order to wait on a condition variable, you must obtain the mutex lock
  • All threads that wait on the same condition variable concurrently must specify the same associated mutex
  • In other words, at any given point in time, each condition variable can be associated with at most one mutex
  • IMPORTANT TIP: Be sure to test the condition (1) after obtaining the mutex lock and before waiting on the condition variable -and- (2) after returning from pthread_cond_wait ( ) (this should be done w/i a loop) 
    /*
 * wait on a condition variable - blocking call
 * - before calling, you must obtain the associated mutex lock
 * - before blocking the thread, pthread_cond_wait() will unlock the mutex (release the mutex lock)
 * - before returning, pthread_cond_wait() will obtain the mutex lock
 *
 * RETURN
 * ======
 * 0 = success
 * else - see discussion on pthreads and errors
 */
int pthread_cond_wait (pthread_cond_t* p_Cond,             // in 
                       pthread_mutex_t* p_Mutex);          // in

/*
 * wait on a condition variable (w/ timeout)
 * - just like pthread_cond_wait() - releases mutex lock and obtains mutex lock before returning
 * - even if timeout occurs, still has to wait to obtain mutex lock (could return a lot later than timeout interval)
 * - returns ETIMEDOUT on timeout
 * - before returning an error on ETIMEOUT wakeup, always check condition (it might have turned true)
 * - see time.h for struct timespec def'n
 * - eg: memset (p_Expire,0,sizeof(struct timespec));
 *       p_Expire->tv_sec = time(NULL) + timeout_interval'
 * 
 * RETURN
 * ======
 * 0 = success
 * else - see discussion on pthreads and errors
 */
int pthread_cond_timedwait (pthread_cond_t* p_Cond,             // in 
                            pthread_mutex_t* p_Mutex,           // in
                            struct timespec* p_Expire);         // in




    /**********
 * an example
 **********/

struct Demo
{
     pthread_mutex_t Mutex;    // mutex
     pthread_cond_t  Cond;     // condition variable
     short nNumItems;          // # items on list
     long lList[5];            // list
};

Demo gsDemo1 = { PTHREAD_MUTEX_INITIALIZER, PTHREAD_COND_INITIALIZER, 0, { 0L, 0L, 0L, 0L, 0L } };

...

// obtain lock
int iRC = pthread_mutex_lock (&gsDemo1.Mutex);
if (iRC != 0) exit -1;

/*
 * obtained mutex lock
 * - check condition before and after waiting on condition variable 
 */

while (gsDemo1.nNumItems == 0)
{
     iRC = pthread_cond_wait (&gsDemo1.Cond,
                              &gsDemo1.Mutex);

     if (iRC != 0) exit -2;
}

/*
 * if here, there are item(s) on list to process (gsDemo1.nNumItems != 0) 
 * -AND- 
 * we have mutex lock
 */

/*
 * process the item(s)
 * - for this demo...we'll print
 */
cout << "gsDemo1.nNumItems: " << gsDemo1.nNumItems << endl;


// unlock
iRC = pthread_mutex_unlock (&gsDemo1.Mutex);    

if (iRC != 0) exit -3;


4. WAKING (BROADCAST/SIGNAL) CONDITION VARIABLE WAITERS

  • Use pthread_cond_signal( ) & pthread_cond_broadcast( ) to wake condition variable waiters
  • Signal wakes up ONE waiting thread
  • Broadcast wakes up ALL waiting threads
  • Unlike waiting on a condition variable, you do not need to obtain the associated mutex lock prior to signalling or broadcasting
  • Before pthread_cond_wait() can return, the condition variable first needs to be signalled or broadcasted. Second, it must wait to obtain the associated mutex. Upon the signal (or broadcast), a context switch will occur and if the mutex can not be obtained, another context switch will occur (you're sleeping waiting for the mutex). This can be avoided if the waker (signaller or broadcaster) releases the mutex prior to signalling (or broadcasting)
  • When in doubt, broadcast. Why? Waiters should be programmed to handle spurious wakeups anyway (they check condition w/i while loop)
  • Use signal when only one thread needs to wake up and any thread will do.
  • I.e. you have an item on a queue which needs to be processed and many identical worker threads waiting to process it 
    /*
 * wake @ most one waiter
 *
 * RETURN
 * ======
 * 0 = success
 * else - see discussion on pthreads and errors
 */
int pthread_cond_signal (pthread_cond_t* p_Cond);            // in 

/*
 * wake all waiter(s)
 *
 * RETURN
 * ======
 * 0 = success
 * else - see discussion on pthreads and errors
 */

int pthread_cond_broadcast (pthread_cond_t* p_Cond);         // in


5. AVOID USING ONE CONDITION VARIABLES FOR MULTIPLE CONDITIONS

  • I.e. a single condition variable to communicate that either the stack is empty or the stack has data
  • If you do, you'll have to broadcast (otherwise you might not wake the appropriate waiter(s))
