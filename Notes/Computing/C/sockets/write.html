write( ) with TCP Sockets

  • Every TCP socket has a send buffer
  • The size of a socket's send buffer can be changed with the SO_SNDBUF socket option
  • When an application calls write( ) for a TCP socket, the kernel copies data from the application's buffer to the socket's send buffer
  • write( ) will NOT return until the last byte is copied from the application's buffer to the socket's send buffer
  • If there is insufficient room in the socket's send buffer for the entire application buffer, the process will be put to sleep
  • This can happen when either the application's buffer is larger than the socket's send buffer or there was already data in the socket's send buffer
  • Therefore write( ) with TCP sockets is a blocking function
  • A successful return from write( ) for a TCP socket only indicates that all the data was successfully written to the socket's send buffer. It does not indicate that the data has been successfully sent to its destination
  • TCP takes the data in the socket's send buffer and sends it to the peer TCP based upon the rules of TCP data transmission
  • The peer TCP must acknowledge the data. Only when the ACK is received, TCP can discard the data from the socket's send buffer


write( ) with UDP Sockets

  • UDP sockets do not really have a send buffer
  • UDP sockets do not have a need for send buffers, since UDP is unreliable, it need not keep a copy of the application's buffer
  • Never-the-less, UDP supports the SO_SNDBUF socket option -- which is simply an upper bound on the maximum sized UDP datagram which can be written to the socket (not the size of a physical buffer)
  • If an application writes a datagram which is larger than the socket's send buffer, EMSGBUF is returned
  • UDP simply prepends an 8 byte header to the user's data and passes the entire datagram to IP
  • IP prepends its header and either adds the UDP datagram to the datalink output queue or, if the datagram is too large, fragments the datagram and adds each fragment to the datalink output queue
  • A successful return from write( ) for a UDP socket indicates that the datagram or all of its fragments have been added to the datalink output queue
  • If there is no room on the queue for the datagram or all of its fragments, ENOBUFS is returned to the application
