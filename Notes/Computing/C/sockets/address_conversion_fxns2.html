IP Addresses & Ports: DNS Names & Similar ↔ Binary Values

  • Convert IP addresses between
    • DNS Names (and Similar) -and-
    • network byte ordered binary values
  • OLD (only handle IPv4)
    • gethostbyname( ): DNS Name (or similar) to IPv4 Address (binary)
    • gethostbyaddr( ): IPv4 Address (binary) to DNS Name (or similar)
    • getservbyname( ): Service Name to Port (via /etc/services)
    • getservbyport( ): Port to Service Name (via /etc/services)
  • NEW (handle both IPv4 and IPv6)
    • getaddrinfo( )


DNS Basics

  • hostnames ↔ IP Addresses
  • simple name: linux_server
  • fully qualified domain name (FQDN): linux_server.chrishardick.com.
  • DNS Entries = Resource Records (RR)
  • There are many different types of RR's
    • Type A: hostname → 32 bit IPv4 address
    • Type AAAA (quad A record): hostname → 128 bit IPv6 address
    • Type PTR (pointer records): IP addresses → hostnames
      • For IPv4 records: 4 bytes are reversed, each byte is converted to decimal (0-255) and in-addr.arpa is appended
    • Type MX: Mail Exchanger. host that accepts e-mail for a domain
    • Type CNAME: Canonial Name


Resolvers and Name Servers

  • Name servers (usually a program called BIND - Berkeley Internet Name Domain)
  • Resolver Functions:
    • gethostbyname( )
    • gethostbyaddr( )
  • Usually /etc/resolv.conf has a list of IP Addresses of local name servers


DNS Alternatives

  • static host file. E.g. /etc/hosts
  • NIS: Network Information System
  • LDAP: Lightweight Directory Access Protocol


gethostbyname( ) and gethostbyaddr( )

  • IP Addresses: DNS Names (and Similar) ↔ Binary Values
  • Older functions - only support IPv4 
    struct hostent
{
     char*  h_name;          // official name of host
     char** h_aliases;       // ptr to array of ptrs to alias names (h_aliases* [])
     int    h_addrtype;      // address type (AF_INET) 
     int    h_length;        // sizeof address (4 bytes)
     char** h_addr_list      // ptr to array of ptrs to IPv4 addresses (struct in_addr* h_addr_list [])
};

#include <netdb.h>


/*
 * DNS Name (or similar) => 32 bit IPv4 address in network byte order
 *
 * RETURN
 * ======
 * non-null ptr = success
 * NULL = error with h_errno set
 */
struct hostent* gethostbyname (const char* hostname);      // in: DNS Name (or similar)


/*
 * 32 bit IPv4 address in network byte order => DNS Name (or similar)
 *
 * RETURN
 * ======
 * non-null ptr = success
 * NULL = error with h_errno set
 * 
 */
struct hostent* gethostbyaddr (const char* addr,           // in:  ptr to in_addr struct (32 bit IPv4 address in network byte order)
                               socklen_t len,              // in:  sizeof(struct in_addr) - 4 bytes
                               int family);                // in:  AF_INET


getservbyname( ) and getservbyaddr( )

  • Services: Name (via /etc/services) ↔ Port # (network byte order)
  • Older functions 
    struct servent
{
     char*  s_name;          // official service name
     char** s_aliases;       // alias list (char* s_aliases[])
     int    s_port;          // port # - network byte order
     char*  s_proto;         // protocol ("tcp"|"udp")
};

#include <netdb.h>


/*
 * Service Name (via /etc/services) => Port # (network byte order)
 * - if protocol is not specified and the service supports multiple protocols, it is implementation dependent
 *   as to which port is returned -- usually not an issue because if a service is supported by multiple protocols
 *   they usually use the same port
 *
 * RETURN
 * ======
 * non-null ptr = success
 * NULL = error
 */
struct servent* getservbyname (const char* servname,       // in: service name
                               const char* protoname);     // in: protocol name ("tcp"|"udp") - optional (pass NULL if N/A)


/*
 * Port # (network byte order) => Service Name (via /etc/services)
 *
 * RETURN
 * ======
 * non-null ptr = success
 * NULL = error
 * 
 */
struct servent* getservbyport (int port,                   // in:  port (network byte order)
                               const char* protoname);     // in:  protocol name ("tcp"|"udp") - optional (pass NULL if N/A)
                               int family);                // in:  AF_INET


getaddrinfo( )

  • Handles:
    • DNS Name → Binary Address
    • Service Name (via /etc/services) → Port #
  • Makes it easier to write protocol independent code - all protocol dependence code is hidden in API
  • Handles both IPv4 and IPv6 
    #include <netdb.h>

/*
 * struct addrinfo
 */
struct addrinfo
{
     int ai_flags;                     // Bitmap. Only used by HINTS structure. 
     int ai_family;                    // AF_UNSPEC, AF_INET, AF_INET6
     int ai_socktype;                  // SOCK_DGRAM, SOCK_STREAM
     int ai_protocol;                  // 0, IPPROTO_UDP, IPPROTO_TCP
     socklen_t ai_addrlen;             // sizeof *ai_addr (socket address struct for the protocol) - AF_INET=16 bytes, AF_INET6=28 bytes
     char* ai_canonname;
     struct sockaddr* ai_addr;         // generic socket address struct

     struct addrinfo* ai_next;         // linked list
};

    /*
 * getaddrinfo()
 *
 * NOTES
 * =====
 * - usual way to call - server: specify service name only
 * - usual way to call - client: specify both host name & service
 * 
 * RETURN
 * ======
 *  0 => OK
 * ~0 => ERROR - use gai_strerror( ) to determine error reason
 */
int getaddrinfo (const char* hostname,           // in:  either: hostname or ASCII address string (IPv4 - dotted decimal, IPv6 - hex string)
                 const char* service,            // in:  either: service name or a ASCII decimal port number string
                 const struct addrinfo* hints,   // in:  NULL if n/a
                 struct addrinfo** result);      // out:
  • HINTS structure
    • Pass NULL to specify no hints. When is this used?
    • The only members which can be set in the HINTS structure:
    • ai_flags
      • ai_flags is a bit map in which zero or more of the following AI_xxx bits can be set:
      • AI_PASSIVE
        • The caller will use the socket as a passive (listening) socket
        • This is typically set for servers
      • AI_CANONNAME
        • Return the canonical name of the host???
      • AI_NUMERICHOST
        • Prevents name-to-address mapping. hostname must be a ASCII address string
      • AI_NUMERICSERV
        • Prevents name-to-service mapping. hostname must be a ASCII decimal port number string
      • AI_V4MAPPED
        • If specified along w/ ai_family = AF_INET6, then returns IPv4 mapped IPv6 addresses corresponding to A records if there are no available AAAA records
      • AI_ALL
        • If specified along w/ AI_V4MAPPED, IPv4 mapped IPv6 addresses will be returned, in addition to any AAAA records belonging to the name
      • AI_ADDRCONFIG
        • Only looks up addresses for a given IP version if there is one or more interfaces (not loopback interface) configured with an IP address of that version
    • ai_family
      • The possible values for ai_family:
      • AF_UNSPEC
      • AF_INET
      • AF_INET6
    • ai_socktype
      • The possible values for ai_socktype:
      • SOCK_DGRAM
      • SOCK_STREAM
    • ai_protocol
    • If a NULL ptr is passed in for the HINTS structure, getaddrinfo( ) assumes
      • ai_flags = 0
      • ai_socktype = 0
      • ai_protocol = 0
      • ai_family = AF_UNSPEC
  • Typical Client: specifies hostname & service. On return, the tcp client will loop thru all returned structures calling socket( ) & connect( ) until a connection succeeds or until all addresses have been tried. See tcp_connect( )
  • Typical Server: specifes only a service and specifies AI_PASSIVE in the HINTS structure. A TCP server will then call socket( ), bind( ), and listen( ). If the server wants to obtains the client's address, it can malloc another socket address structure, using ai_addrlen as the size.
