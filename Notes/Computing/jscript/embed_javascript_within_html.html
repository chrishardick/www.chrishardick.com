Embedding JavaScript Within HTML Documents

JavaScript can be embedded within HTML documents in 4 different ways
  1. Embedded directly in your HTML document between <script> ... </script> tags
  2. From an external file specified as the src attribute of a <script> tag
  3. In an event handler specified by the value of an HTML attribute such as onclick or onmouseover
  4. As the body of a URL that uses the javascript protocol -- not covered

Execution of JavaScript Scripts

  • No matter how you embed your JavaScript code, execution of your script occurs as part of the web browser's HTML parsing and (rendering) displaying process
  • I.e. Script execution is interleaved with HTML parsing and rendering
  • Your scripts should NOT attempt to manipulate objects which have not yet been created
  • I.e. if your script appears in the <head> section, the <body> of the document has yet to be defined therefore your script should NOT attempt to manipulate objects of the body
  • This is not applicable for function definitions
  • Function definitions can appear and manipulate objects of the document which have yet to be created (so long as you do not execute the function prior to the object being created)
  • Because script execution is interleaved with HTML rendering, event handlers may be invoked before a page has been fully displayed. An example I've encountered is a web page with a form with query parameters on the top and a table with query results on the bottom. If the user inputs for a complex query or simply one with a lot of data, the form will be rendered prior to the data.
  • You must make sure any functions which are called in your event handlers have already been defined -- a simple way to guarantee this is to define all of your functions within the <head> section
  • You must also make sure that your event handlers do not attempt to access HTML objects which have yet to be rendered (and created) -- a way to guarantee this is to define your page such that event handlers only refer to previously defined objects
  • You could also use the onload event handler to set a global variable. Your code could then check to see if the global variable and only proceed if the variable has been set
  • You could also check for the existance of the object prior to manipulating it -- defensive programming (a good idea regardless). If the object does not yet exist, it will be null

1. The <script> Tag

  • You can embed JavaScript code directly within your HTML document within <script> ... </script> tags
  • <script> ... </script> tags may appear in either the head or the body of an HTML document
  • You can have as many non-overlapping <script> ... </script> tags as you like -- they are all part of the same JavaScript program (HTML file). I.e. functions and variables defined within one <script> ... </script> tag are accessible to all other scripts within the same file
  • JavaScript code is executed in order of appearance and may be interleaved with HTML. I.e. if you have a script (which writes 'Hello, World1!<br>') followed by HTML ('Hello, World2!<br>') followed by another script (which writes 'Hello, World3!<br>'). The document will be rendered as follows:
    Hello, World1!
    Hello, World2!
    Hello, World3!
  • language/type attributes
    • language
      • language="JavaScript", language="JavaScript1.5"
      • JavaScript is the default value
      • Other values: VBScript
      • Only browsers which support the language will execute the script. I.e. if your script requires JavaScript1.5 (or VBScript), you can prevent browsers which do not support it from executing it
      • deprecated in HTML 4 in favor of the type attribute -- however it is still better supported than the type attribute
    • type
      • type="text/javascript"

2. External JavaScript Files

  • Instead of embedding JavaScript directly within your HTML document, you can reference an external file by using the src attribute of the script element (tag)
  • <script src="http://www.chrishardick.com/javascript/p1.js"></script>
  • JavaScipt files normally use a .js extension
  • This works exactly the same as placing the code within the script tags
  • Allows you to define standard functions/modules

3. Event Handlers

  • For certain element attributes (event handler attributes), HTML allows you to specify JavaScript code which will execute when the event occurs
  • You can specify more than one statement, by seperating the statements by semicolons
  • Common Event Handler Attributes (all HTML event handler attributes begin with on)
    • onclick
      • supported by all button-like form elements, <a>, <area>
      • triggered when user clicks on the element
    • onmousedown, onmouseup
      • usually supported by all elements that support onclick events
      • IE and Netscape support these events for nearly all document elements
      • triggered when user clicks down (onmousedown) or releases (onmouseup) the mouse button
    • onmouseover, onmouseout
      • usually supported by all elements
      • triggered when a mouse pointer moves over (onmouseove) or off of (onmouseout a document element
    • onchange
      • supported by: <input>, <select>, and <textarea> elements
      • triggered when a user changes the value displayed by the element and then tabs or moves focus out of the element
    • onsubmit, onreset
      • supported by <form> tag
      • triggered when the user submits or reset the form
    • onload
      • supported by <body> and <frameset> tags
      • triggered when the document or frameset is fully loaded
    • onunload
      • supported by <body> and <frameset> tags
      • triggered when the browser is about to destroy the current page. I.e. the user choose another page or closed the browser, etc.
