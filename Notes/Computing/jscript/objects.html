JavaScript - Objects

  • Objects are a composite datatype. They allow you to group together variables and functions.
  • The variables are re-named properties
  • The functions are re-named methods
  • Objects are created via the new operator together with a predefined contructor (a type of function)
  • You can create an empty object (an object with no properties) with the Object contructor 
    var my_object = new Object( );
  • You can then add properties and methods to objects on the fly by simple assignment 
    my_object.name = "Chris Hardick";
    my_object.print = print_name( ); // assuming print_name is a function
  • Notice that you do not need var to create properties of an object

Constructors Other Than Object( ) - A Better Way to Create Objects

  • In JavaScript a contructor is any function which is invoked via the new operator
  • Contructors are implicitly passed a reference to a newly created empty object -- via the this keyword 
    // Rectangle constructor
function Rectangle (width, height)
{
     this.m_width  = width;
     this.m_height = height;
}

Methods

  • A method is nothing more than a function which is a property of an object
  • When methods are called, they are implicitly passed a reference to their object -- via the this keyword
  • Note that this is a very loose way to create an object -- but remember, this is simply a scripting language 
    function Rectangle_area()             { return this.m_width * this.m_height; }
function Rectangle_set_width(width)   { this.m_width = width; }
function Rectangle_set_height(height) { this.m_height = height; }

// Rectangle constructor
function Rectangle (width, height)
{
     // properties
     this.m_width  = width;
     this.m_height = height;

     // methods
     this.area       = Rectangle_area;
     this.set_width  = Rectangle_set_width;
     this.set_height = Rectangle_set_height;
}

Prototype Property - An Object

  • Using a constructor to assign methods is ineffecient - everytime you instantiate an object, it gets a fresh copy of each method - increasing the memory required for each instance (which is usually not what you want)
  • The better method to define object methods is via the prototype property
  • In JavaScript, every object has a prototype property
  • Since constructors are functions and functions in JavaScript are implemented as objects, every constructor has a prototype property
  • All properties and methods of the prototype object are shared between all instances of the object
  • This makes the prototype object an ideal place for object methods and any other constant properties - i.e. do not need to be object specific 
    // Rectangle contructor
function Rectangle (width, height)
{
     // properties
     this.m_width  = width;
     this.m_height = height;

     // methods
     this.prototype.area       = Rectangle_area;
     this.prototype.set_width  = Rectangle_set_width;
     this.prototype.set_height = Rectangle_set_height;
  • Prototype properties are accessed just like they're properties of the object (i.e. in the above example, you'd reference the area( ) method using 'r.area( )' -- not 'r.prototype.area', assuming r is an instance of class Rectangle
  • Scope Resolution. I.e. if you have both a property and a prototype property with the same name, and you're reading, the property takes precedence over the prototype property (i.e. it masks the prototype property).
  • You can never write to a prototype property -- only read. If you attempt to write to a prototype property, you will be creating a new property directly in the object (rather than writing to the prototype property
