Client Side JS - Events

  • Event examples: clicked, changed, mouseover, mousemove, keypress, keydown, readystatechange
  • Events have a target - the object on which they occurred
  • Events can also have handlers - which are functions you define to handle the events
  • Event objects are associated with the event and contain details about the event.
  • Event objects are passed as an argument to the event handler.
  • All event objects have a type property which specify the event type and a target property which specifies the target

Registering Event Handlers

There are three ways in which you can register event handlers. You can:

  1. directly assign a JS code snippet to an HTML element attribute,
  2. assign a function to an element property, or
  3. use addEventListener()

1) HTML Attribute

  • The simplest way to set an event handler is to directly assign a code snippet to an HTML attribute
  • The code should be surrounded by quotes
  • If multiple statements are required, they must be separated by semi-colons
  • It's generally a good idea to keep HTML and JS seperate. Therefore this method should probably be used only in the simplest cases.
  • By convention, HTML attributes representing event handlers are named "on" followed by the event name -- i.e. onclick
  • Example: 
    <button onclick="alert('Event Handler via HTML attribute');">Click Me</button>

2) Element Properties

  • By convention, event handler properties are named "on" followed by the event name -- i.e. onchange, onload, onmouseover, ...
  • Event handler properties are case sensitive
  • Advantages: widely supported
  • Disadvantages: assumes there will be at most one handler
  • Examples: 
    window.onload = function() { ... };

form = document.getElementById("form");
form.onsubmit = function() { ... };

3) addEventListener()

  • Supported by all browsers other than IE8 and earlier
  • All elements which can be an event target define an addEventListener() method which you can use to register event handlers for the given target
  • You can register multiple listeners for the same element. The event handlers will be called in the order in which they were registered.
  • Calling addEventListener() more than once on the same object with the same argument set has no effect. The handler will only be called once
  • addEventListener() takes three arguments.
    1. name of the event (not including the 'on' prefix)
    2. the function which should be invoked when the event occurs
    3. boolean - whether or not the event listener is a capturing event. Normally you just pass false.
  • There is also a removeEventListener() method which accepts the same three arguments and removes the event handler from the object 
    var e = document.getElementById("my_element");

e.addEventListener("click", function() { alert ("Event Handler set via addEventListener"); }, false);
  • IE8 and earlier supported similar functionality via the attachEvent() and detachEvent() methods. They accept two parameters -- as they do not support event capturing and the first paramter accept the event name with the "on" prefix
  • IE9 was first released in March, 2011
  • Therefore, a common method to write portable code is: 
    var hndlr = function() { alert("Portable Code"); };

e = document.getElementById("my_element");

if (e.addEventListener)
{
    e.addEventListener("click", hndlr, false);
}
else if (e.attachEvent)
{
    e.attachEvent("onclick", hndlr);
}

Event Handler Invocation

Event Handler Argument

  • Event handlers are normally invoked with an event object as their single argument
  • The properties of the event object provide details about the event
  • The type property specifies the type of event
  • Note that IE8 and before, event handlers registered by setting an element property are an exception to this. Rather than passed as an argument, the event object is accessed via window.event. Event handlers registerd via attachEvent() are passed an event object (however they can also access the event object via window.event) 
    // a portable handler
function handler (event)
{
    lcl_event = event || window.event
    ...
}

Event Handler Context

  • Event handlers which are registered either via an element property or via addEventListener are invoked as methods of the event target (the element which generated the event).
  • Therefore, this refers to the event target
  • This is not true for handlers registered via attachElement() - i.e. IE8 and prior

Mouse Events

  • All mouse event objects have clientX and clientY properties which specify the position of the mouse
  • The button and which properties specify which mouse button was pressed
  • The altKey, ctrlKey, metaKey, and shiftKey properties are set to true when the corresponding keyboard keys are also held down
  • mousemove event is triggered any time the user moves or drags the mouse
  • mouseover event is triggered any time the user moves the mouse over a new element
  • mouseout event is triggered any time the user moves the mouse is no longer over an element
  • mousedown event is triggered when the user presses a mouse button
  • mouseup event is triggered when the user releases a mouse button
  • click event is triggered after a mousedown/mouseup sequence
  • dblclick (double click) event is triggered after two mousedown/mouseup sequences in quick succession

Key Events

  • When a web browser has keyboard focus, it generates events each time the user presses or releases a key
  • Keyboard events are triggered on whatever document element has keyboard focus and then they bubble up to the document and window.
  • Keyboard event objects have a keyCode field which indicates which key was pressed or released
  • Keyboard event objects also have altKey, ctrlKey, metaKey, and shiftKey properties set to true when the corresponding modifier keys are also pressed
  • keydown and keyup events are lowlevel events which are triggered whenever a key (even a modifier key) is pressed or released
  • When a keydown event generates a printable character, a keypress event is triggered after the keydown event, but before the keyup event
  • The keypress event is a higher level event and its event object specifies the key that was generated, not the key that was pressed
