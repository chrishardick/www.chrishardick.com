Git

Configuration

git init

  • Create git repository
  • git init [--bare]
  • Use the bare option to create a bare repository (as opposed to a working repository)
  • Central repositories should be created as bare repositories. Bare directories do not contain working (i.e. checked out) versions of the files. They also store the git revision history in the root folder rather than in the .git subdirectory. By convention, bare repositories are normally named with .git extension
  • git init --bare foo.git

git clone

  • git clone <url>
  • Clone repository (will make directory for you)
  • You will have one branch (main). run git branch to verify
  • You never want to work in the main branch - you essentially want to treat it as read-only
  • Examples: 
    git clone ssh://john.smith@smith.com:[port]/dir

git clone https://github.com/google/googletest

git clone vs. github fork

  • fork is a github concept. It creates a copy of the repository in your own github account
  • One reason you may fork as opposed to clone is because you do not have the proper permissions on the repository
  • In that case, you'd create a fork, commit your changes to it and enter a PR referencing your fork
  • From the URL of the repository you wish to create a PR into:
    • 'New Pull Request'
    • Click compare across forks link
    • Enter a link to your fork under head repository
    • Click 'Create pull request'

git remote [-v]

  • To see which remote servers you have configured, run git remote - if you've cloned your repository, you should see at least origin. This will display the shortname for the remote server
  • Use the -v option to also see the actual URL of the remote server
  • To see which remote servers you have configured, run git remote

git remote add <remote_name> <url>

  • Add a new remote
  • git remote add blah chris@blah.com:[port]/dir
  • To see which remote servers you have configured, run git remote - if you've cloned your repository, you should see at least origin. This will display the shortname for the remote server
  • Use the -v option to also see the actual URL of the remote server
  • To see which remote servers you have configured, run git remote

git checkout

  • Switch branches or restore working tree files
  • git checkout -b new_branch - create a new branch and switch to it
  • git checkout branch - switch to an existing branch
  • git checkout commit_hash - restore to previous commit - use git log for a list of commit hashes
  • Always create a branch rather than working in main. I.e. dev
  • Before switching branches, make sure all your changes are committed. If not, you will be warned that changes will be lost.
  • For example: git checkout -b dev

git branch

  • display a list of all branches

git status

  • display a list of all branches
  • git status -u will show individual files in untracked directories

Diffs

  • To get a list of files which changed 
    git diff --name-only tag_or_branch1 [tag_or_branch2]
  • Diff against main - see handy script listed below 
    git difftool --extcmd="diff -w" --no-prompt main <file> >file.diff 2>&1
  • Diff against remote branch
    • Create a new remote. E.g. git remote add rmt_name git_url
    • Fetch remote repo. E.g. git fetch rmt_name
    • Get list of files which have changed git diff --name-only rmt_name/main

git add

  • mark files in which changes will be committed upon a git commit

git rm

  • remove files from the index and the working directory. History will remain as the file will remain in the object store

git commit

  • commit changes (marked via git add) to the local repository

git merge

  • Merges changes into the current branch
  • For instance, let's say you've been working on branch foo and all your changes have been committed
  • Let's also say that you're ready to merge your changes into main
  • The following would merge your changes into main 
    # switch to main branch
git checkout main

# merge changes in foo to main branch
git merge foo

git fetch

  • Download branches and/or tags from another repository
  • By default, tags are not pulled down, if you want to copy tags, use the following: 
    git fetch
git fetch --tags

# you can now switch to a tag
git checkout your_tag

git pull

  • Performs a git fetch followed by a git merge
  • In other words, download from the remote repository and merge its changes into the current repository

Updating Remote Repositories

KEY CONCEPT: Before attempting to update remote branches, all changes must have already been committed to the local repository

Bring Local Main Up-to-Date

  • this is only necessary if the remote main branch is ahead of our local main branch 
    #
# Switch to local main branch
# - make sure all your changes have been committed. Otherwise, you'll receive an error
#
git checkout main

#
# bring local main up-to-date with 'origin main'
# - git pull is the equivalent of git fetch followed by git merge
#
git pull origin main

Merge Changes - Development Branch

    #
# switch to your development branch
#
git checkout <branch>

#
# merge remote changes to main into your development branch
#
git rebase main

Merge Changes - Main Branch

    #
# switch to main branch
# 
git checkout main

#
# merge changes from development branch into main
#
git merge <branch>

Push Changes to Remote Repository

  • git push [origin main]
  • specify origin main for 1st push

Show History

  • git log [-p] - lists commits in reverse chronological order. -p shows diffs

Appendix

  • Handy diff script - mygitdiff.sh 
    for file in $@
do
    if [ -f ${file}.diff ]; then
        cmd="mv ${file}.diff ${file}.diff.sav.`date +%Y%m%d%H%M%S`"
        echo "${cmd}"
        echo ""
        $cmd
    fi

echo "==================================================" >$file.diff
date                                                      >>$file.diff
echo ""                                                   >>$file.diff
echo "$file.diff"                                         >>$file.diff
echo ""                                                   >>$file.diff
echo "DIR: $PWD"                                          >>$file.diff
echo ""                                                   >>$file.diff
echo "OUTPUT BY ${0}"                                     >>$file.diff
echo ""                                                   >>$file.diff
echo "==================================================" >>$file.diff
echo ""                                                   >>$file.diff

git difftool --extcmd="diff -w" --no-prompt main $file >>$file.diff 2>&1
done
