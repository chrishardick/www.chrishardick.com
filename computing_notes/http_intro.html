HTTP

  • Hypertext Transfer Protocol
  • An application layer protocol
  • A line based protocol
  • All HTTP Messages have the same basic format: 
    START-LINE (typical request - GET / HTTP/1.1) (typical response: HTTP/1.1 200 OK)
HEADERS (optional tag:value lines)
BLANK LINE (indicating the end of the header)
BODY (optional. the data associated with the message. The size of the body is usually specified in the headers.)
  • Usually sent over TCP or TLS-encrypted TCP. However could be sent over any reliable protocol
  • HTTP is stateless, but not sessionless
  • HTTP/1.0 opened up a new TCP connection for each request/response.
  • HTTP/1.1 introduced pipelining (allowing several simultaneous requests to be sent without waiting for responses) and persistent connections - the TCP connection could be partially controlled using the Connection header
  • HTTP/2 multiplexed messages over a single connection
  • HTTP/1.0 and HTTP/1.1 messages are human-readable.
  • HTTP/2 messages are encapsulated in a binary structure (frames) making them impossible to read directly -- however the basic messaging still remains the same
  • requests are sent from clients (user agents) and responses from web servers

Basic HTTP Message Flow

  1. TCP connection opened
  2. Send HTTP Request
  3. Read HTTP Resonse
  4. TCP connection closed (HTTP/1.0) or left open for re-use (HTTP/1.1 or above)

HTTP Message Structure

  1. Start-line - for Requests - specifies the request type, path and protocol; for Responses - specifies the protocol along with the return code for the corresponding request (basically success or failure). For responses, the start-line is more aptly called a Status line
  2. Headers - Optional. Tag: Value
  3. Blank line - Indicating al meta data has been sent
  4. Body - Optional. Data associated with the message. The size of the body is specified in the Headers

Request Methods

GET

  • Get an HTML document
  • Request and Response 
    REQUEST (from client)                       RESPONSE (from server)

GET / HTTP/1.1                              HTTP/1.1 200 OK
Host: www.chrishardick.com                  Connection: Keep-Alive
Accept-Language: en                         Keep-Alive: timeout=5, max=999
                                            Date: Thu, 06 Sep 2018 20:49:02 GMT
                                            Server: Apache
                                            Last-Modified: Wed 05 Sep 2018 15:20:19 GMT
                                            ETag: "11111111-2222-3333333333333"
                                            Accept-Ranges: bytes
                                            Content-Length: 12345
                                            Content-Type: text/html; charset=utf-8

                                            <!DOCTYPE html... -- 12,345 byte document...
  • Request Details
    • GET - method
    • / - path. in this case we're requesting the home page of the website.
    • HTTP/1.1 - protocol version
    • tag : value - optional headers (line delimited)
    • Blank line - indicating all meta data has been sent
    • body - the above request does not contain a body
  • Response Details
    • HTTP/1.1 - protocol version
    • 200 - status code. E.g. 200=OK/success; 404=Not Found; 401=Unauthorized; 403=Forbidden; 301=Moved Permanently
    • OK - status text. Purely informational (to make more human readable)
    • tag : value - headers
    • <!DOCTYPE html... - message body

POST

  • POST requests are used to send data to a web server (usually a set of name:value pairs from an HTML form
  • Includes a body of data after the headers
  • Normally, the data is handled by a dynamic module (cgi or similar) which processes the data

HEAD

  • Return info about the document, but not the physical document

>PUT

  • Similar to POST, except idempotent. I.e. single or multiple calls to the same URI result in the same result.
  • Typical use - send a new document to the server to publish @ the given URI or replace an existing document
  • For security reasons, this request method is normally disabled by default

DELETE

  • Delete the specified document
  • For security reasons, this request method is normally disabled by default
