make

  • A build utility which can help manage the compilation and linkage of programs

Basic Usage

make [-f makefile] [option(s)] [target(s)]
  • If you do not specify a makefile, make looks for a file named Makefile or makefile (in that order) in the current directory

Makefiles

  • Makefiles essentially consists of rules
  • Each rule specifies a target, a list of dependencies, and a list of commands
  • The list of commands is also known as a recipe.
  • Each line in the recipe must start with a tab (or the first character in the value of the .RECIPEPREFIX variable)
  • The first rule listed in a makefile is the default rule. I.e. it is the rule executed if you do not specify a target when invoking make
  • automake is a tool which can help you generate makefiles
  • autoconf and cmake are tools which help generate platform specific build instructions

Comments

  • Make supports single line comments which start from a hash symbol (#) to the end of a line

Rules

target [target ...]: [dependencies]
    commands

# a rule example
foo.o: foo.cpp foo.h
    g++ -c foo.cpp

Phony Targets

  • A phony target is a target in which you're not really trying to build. It's more of a name for a list of instructions to be executed. E.g. make build, make clean
  • It's a good idea to explicitly declare your phony targets to avoid an unintentional conflict. I.e. if someone creates a file named build or clean, your phony target will cease to work. Since it has no dependencies, it will always be up-to-date
  • To explictly declare a target as a phony target, you make it a dependency of a special target .PHONY 
.PHONY: build clean

Macros

  • A macro is a variable which holds a string 
MACRO = definition      # by convention, macros are usually defined in uppercase

# macro expansion
$(MACRO)
${MACRO}    # equivalent

# a macro example
CXX=g++

foo.o: foo.cpp foo.h bar.h
    $(CXX) $(CXXFLAGS) -c foo.cpp

Implicit Rules

  • Some rules are so frequently used, they are defined by implicit rules
  • There are both built-in and user-defined implicit rules
  • Built in implicit rules use a bunch of predefined variables - a few of which are listed below
  • An example of a build-in implicit rule is generating an object file from a c or c++ source file

Predefined Variables

CC
program used to compile C programs
CXX
program used to compile C++ programs
AR
archive program used to make libraries
CFLAGS
options to give the C compiler
CXXFLAGS
options to give the C++ compiler
ARFLAGS
options to give the archive program

Pattern Rules

  • You can define an implicit rule by writing a pattern rule
  • In a pattern rule, the target contains a '%' character (exactly one of htem).
  • $< target file name
  • $@ source file 
    %.o: %.c
    $(CC) -c $(CFLAGS) $< $@
