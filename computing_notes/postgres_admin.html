PostgreSQL: Administration

Installing PostgreSQL

Debian-based Systems

apt-get update
apt-get install postgresql postgres-contrib     # -contrib package adds additional utilities and functionality

pg_hba.conf

  • The pg_hba.conf file controls client authentication
  • hba - host based authentication
  • The file is usually located at /etc/postgresql/[version]/main/pg_hba.conf
  • The file is read on server startup
  • After editing the file, it is best to restart the server - systemctl restart postgresql
  • The file contains a set of records. One record per line. Records cannot extend beyond a single line
  • Blank lines are ignored, as is any text after the # (comment) character
  • Each record consists of whitespace (space and/or tab) delimited fields
  • Fields can contain whitespace if the field value is double-quoted
  • Field 1 - Connection type
    • local - Unix domain socket
    • host - either a plain or SSL-encrypted socket
    • hostssl - SSL-encrypted socket
    • hostnossl - non SSL-encrypted socket
  • Field 2 - Database
    • all - all databases
    • sameuser
    • samerole
    • replication
    • dbname
    • comma delimited list
    • @filename - include names from file - filename
  • Field 3 - User
    • all - all users
    • username
    • +groupname
    • comma delimited list
    • @filename - include names from file - filename
  • Field 4 - Address
    • N/A for local
  • Field 5 - Method
    • trust - do not require a password
    • reject
    • md5 - send encrypted password
    • password - sends password in clear text
    • gss
    • sspi
    • ident
    • peer
    • pam
    • ldap
    • radius
    • cert
  • Field 6 - Options
    • Set of options in the format NAME=VALUE

postgres User

  • The postgres user is created automatically when postgreSQL is installed.
  • The login is locked. I.e. the login does not have a password. The only way you can log in to it is by using su as a superuser

Database Roles

  • PostgreSQL manages database permissions using the concept of roles
  • Database Roles are global across a database cluster installation
  • CREATE ROLE role-name <attribute list>;
  • DROP ROLE name;
  • You can also use the postgreSQL UNIX command createrole --interactive to create a role via the UNIX command line. The interactive flag will cause createrole to prompt you for the necessary values
  • Database Roles can have a number of attributes:
    • LOGIN - specifies a given role has LOGIN privileges
    • SUPERUSER - specifies a given role has SUPERUSER privileges. A superuser bypasses all permission checks - except the right to login in. Only a superuser roll can do this.
    • CREATEDB - specifies a given role has permission to create databases
    • CREATEROLE - specifies a given role has permission to create, alter or drop roles. A role with this attribute can also grant or revoke membership to a given role. Superuser status is required to alter a superuser role.
    • REPLICATION - specifies a given role has permission to initiate streaming replication. A role used for streaming replication must also have LOGIN privileges - i.e. CREATE ROLE name REPLICATION LOGIN
    • PASSWORD - specifies a password required for the given role - i.e. CREATE ROLE name PASSWORD 'string' A password is only significant if the client authentication method requires the user to supply a password when connecting to the database.
  • ALTER ROLE can be used to modify the attributes of a role after creation
  • It's a good idea to create a role that has both CREATEDB and CREATEROLE privileges to avoid using superuser privileges for tasks which do not require it

Role Membership

  • In PostgreSQL, you can create a role that represents a group
  • Typically a role being used as a group would not have the LOGIN attriute
  • CREATE ROLE groupname attribute_list
  • Once the group role exists, you can add and remove members using the GRANT and REVOKE commands
  • GRANT group_role TO role1, ...;
  • REVOKE group_role FROM role1, ...
  • You have to specify the INHERIT attribute in order to use the privileges of group roles which you are a member. Otherwise you need to use SET ROLE role to temporarily become the group role (and no longer in your login role)

Quick Start - Create User

  • Edit /etc/postgresql[version]/main/pg_hba.conf to have this line -- which will allow local connections without a password: 
    local   all             all                                     trust
  • Restart the postgreSQL server 
    systemctl restart postgresql
  • As superuser, use su to log in as the postgres user 
    su - postgres
  • Create a new role (as user postgres). The interactive mode will cause you to be prompted to enter the necessary values. 
    createuser --interactive
  • Create a database with the same name as the role (as user postgres). PostgreSQL requires there to be a datbase with the same name as the role being used to login which the role has access to. 
    createdb <rolename>
  • Using a regular UNIX login you should now be able to access psql 
    psql [dbname [username]]
