Python: multiprocessing Module

  • Process based parallelism
  • See also threading module - which provides thread based parallelism
  • Due to the GIL - Global Interpreter Lock which only allows a single thread within a process to execute Python bytecode in the interpreter at a time, process based parallelism is usually more efficient than thread based parallelism

Process Class

import os

from multiprocessing import Process

def child_start ():

    print ("child_start: pid=%d" % os.getpid())

print ("main: pid=%d" % os.getpid())

p = Process (target=child_start, args=())

p.start()       // start child process

p.join()        // block until it completes

Communicating Between Processes - Queue and Pipe

Queue Class

  • Basically a clone of Queue.queue
  • Queues are thread and process safe

Pipe Class

  • Returns a pair of communication objects connected by a pipe - which by default is duplex
  • Each connection object has send() and recv() methods
  • Note that data in a pipe may become corrupted if two processes (or threads) try to read from or write to the same end of a pipe at the same time

Lock Class

  • Similar to threading.Lock but for multiple processes as opposed to multiple threads
  • The Lock class supports two basic methods: acquire() and release()
  • acquire() is used to obtain a lock. It will block if the lock is currently locked
  • release() is used to release a lock. It will throw a RuntimeError if called on an unlocked lock 
from multiprocessing import Process,Lock

def f (l, i):
    l.acquire()
    
    try:
        print ("Hello, world!", i)

    finally:
        l.release()

lock = Lock()

for num in range (0,9):
    Process(target=f, args=(lock,num)).start()
