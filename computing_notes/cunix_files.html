C/UNIX: Files

  • In UNIX, everything is a file
  • Programs can interact with serial ports, printers, sockets and other devices in exactly the same way they would a file. Directories are also files (albeit a special type)
  • Two methods can be used to interact with files: System Calls and Library Functions. Library Functions are mainly used for files and terminal I/O. However, when you need explicit control over devices, you're better off with low-level system calls, as they do not involve buffering

I. System Calls

  • We can access and control files (and devices, etc.) using system calls.
  • System calls are a direct interface to the OS (Linux/UNIX), provided by the OS.
  • The basic system calls relating to files are:
    • open()
    • close()
    • read()
    • write()
    • ioctl()
    • Random Access: lseek()
    • Status: fstat(), stat(), lstat()

open() 
#include <fcntl.h>

//
// open the file specified by pathname
// 
// flags (bitmap)
// ==============
// flags must contain one of the following:
// - O_RDONLY, O_WRONLY, O_RDWR - open file read only, write only or read-write
// 
// other flags:
// O_APPEND     - append mode. before each write, the file offset is positioned at the end of the file
//              - the file offset and the write operation are performed as an atomic operation
//              - can lead to problems on NFS filesystems 
// O_CREAT      - if pathname does not exist, create it as a regular file
//              - the mode argument specifies the file mode bits to be applied when a new file is created
//              - the effective mode is modified by the process's umask
// O_EXCL       - ensure this call creates the file
//              - in general, used in conjunction with with O_CREAT
//              - if file already exists, open() will return an error
//              - on NFS, only supported when using NFSv3 or later on kernel 2.6 or later
// O_TRUNC      - if the file already exists and is a regular file and the access mode allows writing
//                truncate the file to 0 bytes
//
// return
// ======
// file descriptor - essentially a non-negative integer which is an index into the process's table
//      of open file descriptors. the fd is used in subsequent calls - e.g. read(), write(), etc.
// on error, -1 is returned and errno is set with the applicable error
//

int open(   const char* pathname
            ,int flags
            ,mode_t mode            // OPTIONAL: ignored if O_CREAT nor O_TMPFILE is specified
            )

II. Library Functions

  • Provide a higher level interface to files than system calls
  • They're part of ANSI C, so they're portable across different operating systems
  • Provide Buffered I/O, which reduces the number of system calls made (which are expensive) and insures that data is correctly written to the device (i.e. different devices have different block sizes, etc.)
  • The basic Library Functions relating to files are:
    • fopen( )
    • fclose( )
    • fread( )
    • fwrite( )
    • Buffering: fflush( ), setvbuf( )
    • Random Access: fseek( ), fgetpos( ), fsetpos( ), ftell( ), rewind( )
    • Status: fstat( ), stat( ), lstat( )
    • fgetc( ), getc( ), getchar( )
    • fputc, putc( ), putchar( )
    • fgets( ), gets( )
    • Formatted I/O: printf( ), fprintf( ), sprintf( ), scanf( ), fscanf( ), sscanf( )

1. fgets( ) - Get Input From a File 1 Line At a Time

    #include <stdio.h>

char* fgets (   char* s,        // OUT: Preallocated Buffer to Write to	
                int size,       // IN:  Read @ Most size-1 characters
                FILE* stream);  // IN:  Stream to read from (stdin or any other stream)

RETURN
======
s on Success
NULL on Error, EOF, or No Characters Read
  • Read @ most size-1 characters from stream and store them in s
  • Reading stops after EOF or newline (\n)
  • If a newline is read, it is stored in the buffer
  • A NULL character is stored after the last character read
