#include <unistd.h>

int close (int fd);             // in:  file descriptor to close


close( ) with TCP Sockets

  • See also shutdown( ) and SO_LINGER socket option
  • Mark socket as closed
  • Once close( ) is called, a process can no longer write( ) or read( ) the given socket descriptor
  • Returns immediately (asynchronous function call) - can be modified with the SO_LINGER socket option
  • Decrements the reference count for the descriptor
  • If reference count is less than or equal to 0 (zero), TCP's 4 segment connection termination sequence will begin (FIN will be sent)
  • If you want to initiate TCP's 4 segment connection termination sequence, regardless of the descriptor's reference count, call shutdown( ) rather than close( )

close ( ), SO_LINGER, and shutdown( )

  • Since close( )--by default--returns immediately, the process has no way of knowing:
    1. if the peer TCP received and acknowledged the data
    2. if the peer application read and processed the data
  • By calling close( ) with the SO_LINGER socket option specified, close( ) will not return until either a (1) linger timeout occurs (timeout value specified by application) or (2) the peer TCP has received and acknowledged the data. Therefore, by specifying an appropriate timeout value, we can be assured that the peer TCP has received and acknowledged the data. Note that we still don't know whether or not the peer application has received and processed the data
  • In order to be certain that both (1) the client TCP has received and ACKed the data and (2) the peer application has received and processed the data, you need to call shutdown(SHUT_WR), followed by read( )
