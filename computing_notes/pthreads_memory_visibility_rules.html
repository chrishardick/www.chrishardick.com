Memory Visibility Rules

  • This page discusses memory visibility between threads (i.e. sharing data between threads)
  • It discusses the reasons why you have to use mutexes (or read-write locks) even if you have many reader thread(s) but only one writer thread of a particular area of memory
  • These rules exist because of the way multi-processor memory architectures are designed, with separate processors each having their own memory caches
  • With each processor having its own memory cache and the possibility of different threads running in different processors attempting to share data between, these rules govern when the various caches (and main memory) are guaranteed to be sunk up


  1. Whatever memory values thread T1 can see when it creates a new thread T2, can also be seen by T2
    • If T1 sets a global variable and then calls pthread_create( ) to create T2, T2 is guaranteed to see the correct value for the global variable (that set before the thread was created). On the otherhand, if T1 had created T2 prior to setting the global variable, T2 is not guaranteed to see the correct value of the global variable.

  2. Whatever memory values thread T1 can see when it unlocks mutex M, can also be seen by thread T2 when it unlocks mutex M

  3. Whatever memory values thread T1 can see when it terminates, can also be seen by thread T2 that joins with T1

  4. Whatever memory values thread T1 can see when it signals or broadcasts a condition variable (CV) can also be seen by any thread (T2,...TN) that is awakened by the broadcast/signal. This is an important rule because a thread need not hold a mutex lock when it broadcasts/signals a condition variable
