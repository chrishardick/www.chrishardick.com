Linux - init

init systems

The purpose of an init system is to initialize the system -- i.e. start the userspace applications after the kernel has loaded -- and manage services while the system is running

  • System V - older -- rc scripts and inittab to respawn
  • Upstart - newer
  • systemd - newest -- backwards-compatible with System V commands and initialization scripts

Run Levels

  • Run Level 0 -- system shutdown
  • Run Level 1 -- single user mode
  • Run Level 2 -- multi-user, network enabled, text mode
  • Run Level 3 -- multi-user, network enabled, text mode
  • Run Level 4 -- multi-user, network enabled, text mode
  • Run Level 5 -- multi-user, network enabled, graphical mode
  • Run Level 6 -- system reboot
  • 5 - Run

systemd

  • /etc/systemd/system - init scripts
  • /etc/systemd/system/multi-user.target.wants/SERVICE.service
  • Use systemctl to enable the service -- sudo systemctl enable service.service. This will create a symlink in /etc/systemd/system/multi-user.taget.wants
  • The file should contain a line 'Restart=always' under the [Service] section of the file to enable the service to respawn after a crash
  • systemctl - central tool for controlling the init system

systemctl

  • To bring up a systemd service: sudo systemctl start application[.service]
  • To bring down a systemd service: sudo systemctl stop application[.service]
  • To restart (bounce) a systemd service: sudo systemctl restart application[.service]
  • To have a systemd service reload its configuration (if supported): sudo systemctl reload application[.service]
  • To have a systemd service automatically start at boot (creates a symlink): sudo systemctl enable application[.service]
  • To no longer have a systemd service automatically start at boot (removes a symlink): sudo systemctl disable application[.service]
  • To check the status of a systemd service: sudo systemctl status application[.service]
  • To check if a given systemd service is currently executing (will return a 0 exit code if active): sudo systemctl is-active application[.service]
  • To check if a given systemd service is enabled (i.e. configured to automatically start at boot time) - will return a 0 exit code if enabled: sudo systemctl is-enabled application[.service]
  • To check if a given systemd service is in a failed state (i.e. there was an error starting it) -- will return a 0 exit code if in failed state: sudo systemctl is-failed application[.service]
  • To see a unit's dependency tree: sudo systemctl list-dependencies application[.service]. Use the --reverse flag to see what is dependent on a given application, use the --before flag to show applications which depend on the specified application starting before them (the --after flag is similar)
  • To show an application's properties: sudo systemctl show application[.service]
  • To mask an application (make it unstartable -- either automatically or manually -- by linking it to /dev/null): sudo systemctl mask application[.service] -- use unmask to unmask it

    systemd unit files

    • Usually stored in /lib/systemd/system -- these are the default files
    • Files stored in /etc/systemd/system take precedence over their counterparts in the lib directory. If you wish to edit a file, you should edit the etc version.
