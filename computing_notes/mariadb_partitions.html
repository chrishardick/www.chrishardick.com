MySQL - Table Partitions

  • Table Partioning is when you divide table data across multiple storage objects called partitions
  • E.g. partitioning a table by date allows you to easily trim off older data

Horizontal vs. Vertical Partitioning

  • Horizontal Partioning - partitioning via rows. Different rows can go to different partitions
  • Vertical Partioning - partitioning via columns. Different columns go to different partitions - not supported by MySQL.

Benefits of Partioning

  • The primary purpose people use partitions is efficient deletion. I.e. deleting old records, etc.

Basics

  • To test if your MySQL engine supports partitioning - execute SHOW PLUGINS and check for partition is ACTIVE
  • Partitions are always numbered sequentially starting from 0 when created.
  • Partition names are not case sensitive
  • All columns used in a partition expression must be present in every unique key in the table
  • There are 4 partition types available:
    • RANGE
    • LIST
    • HASH
    • KEY

RANGE Partioning

  • Assigns rows to partitions based on column values which fall within a specified range.
  • RANGE partitioning works best for deleting old records
  • Note the MAXVALUE expression below. This covers you when someone tries to add a record with a date greater than Dec 31, 2024.
  • ALTER TABLE logs DROP PARTITION partition2021

        ,dt datetime
        ,txt varchar(180)
        ,primary key (id, dt)
        )
PARTITION BY RANGE (YEAR(dt))

    ,PARTITION partitionMAX  VALUES LESS THAN MAXVALUE
