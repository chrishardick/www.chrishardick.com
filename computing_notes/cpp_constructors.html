C++ Constructors

  • A Special Member Function automatically called when an object of a class is declared.
  • Provides an opportunity to initialize an object at creation time. Thereby ensuring valid objects (i.e. data members contain only valid data)
  • Constructors ALWAYS have the same name as the class and have NO return type. It is a syntax error to give a constructor a return type (even void)
  • Constructors may be overloaded
  • Constructors (like other functions) may have Default Parameters
    • class CBox 
{
	public:
		// Constructor(s)
		CBox (double dL=1.0, double dW=1.0, double dH=1.0);

	private:
		double m_dLength, double m_dWidth, double m_dHeight;

};


I. Default Constuctor

  • A Constructor which is able to accept 0 (NO) Arguments.
  • If you do NOT supply any constructors, the C++ Compiler will provide you with a default constructor which does NOTHING 
    CObject::CObject() {}  // default constructor provided by C++ compiler


II. Copy Constuctors

  • A Copy constructor is a constructor which accepts a constant reference to an object of the same type, for the purpose of initializing the new object (the job of all constructors) with the inputted object
  • If you do NOT provide a Copy Constructor for your class, the C++ Compiler will provide you with a Default Copy Constructor which utilizes memberwise initialization for all data members of your class: 
    CObject::CObject (const CObject& CObjectToCopy) 
{ 
     // Memberwise Initialization 
}
  • The reason for passing the object to be copied by reference (as opposed to by value) is to avoid an infinite loop. For example: 
    CObject x = y;
  • Assuming y is a CObject instance, the copy constructor will be called (y will have to be passed in--if it's passed in by value, the copy constructor needs to be called...)

Overriding the Default Copy Constructor

  • Sometimes, you need to override the default copy constructor.
  • Any time your class involves dynamic memory allocation, you need to implement your own copy constructor.
  • Take a look at the following example: 
    class CObject 
{
	char* m_szMsg;

	CObject (char* szMsg) { m_szMsg = new char[strlen(szMsg) + 1]; strcpy (m_szMsg, szMsg); }
}

...

CObject x = y;	// ERROR
  • Assuming y is a CObject instance, the copy constructor will be called & the data members will be copied over using memberwise initialization.
  • The issue is that both objects will now point to the same string!!!
  • Change it in 1 & you'll change it in the other.
  • Delete one of the objects & the other object will be pointing to unallocated memory.
  • SOLUTION 
    class CObject 
{
	char* m_szMsg;

	// Constructor
	CObject (char* szMsg)                  { m_szMsg = new char[strlen(szMsg) + 1]; strcpy (m_szMsg, szMsg); }

	// Copy Constructor
	CObject (const cObject& CObjectToCopy) { m_szMsg = new char[strlen(CObjectToCopy.m_szMsg) + 1]; strcpy (m_szMsg, CObjectToCopy.m_szMsg); }
};

...

CObject x = y; // NOW WE'RE OKAY
  • Keep in mind that any time you pass an object by value, the copy constructor is called!


III. Declaring An Arrays of Objects And Calling A Non-Default Constructor

  • You declare an array of objects exactly the same as you declare an array of scalers
  • Each element of the array causes the default constructor to be called
  • If you would like to use another constructor, the following syntax can be used: 
    Cat myCats[4] = {
	Cat ("Chris",GRAY),
	Cat ("Charles",ORANGE),
	Cat ("Showball",WHITE),
	Cat ("SOCKS",BLACKANDWHITE)
};
  • If you're dynamically allocating an array of objects, the above syntax is not supported. 
    Cat* myCats = new Cat[4];  // default constructor called 4 times
