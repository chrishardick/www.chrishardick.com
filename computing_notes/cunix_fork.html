C/UNIX: fork() and Related Functions

fork ()

  • A system call
  • Create a child process which is virtually identical to parent process
  • All file descriptors remain open across both child and parent processes 
/*
 * RETURN
 * ======
 * on success
 * - IN PARENT: PID of child process
 * - IN CHILD: 0
 * 
 * on error
 * - IN PARENT: -1 (no child process is created)
 */

#include <sys/types.h>
#include <unistd.h>

pid_t fork (void);

wait(), waitpid()

#include <sys/types.h>
#include <sys/wait.h>


//
// RETURN
// ======
// on success, returns the process ID of the child who terminated
// otherwise, returns -1 (errno will be set)
//
pid_t wait (int* status)    // see below


//
// RETURN
// ======
// on success, returns the process ID of the child whose state has changed
// otherwise, returns -1 (errno will be set)
//

pid_t waitpid ( pid_t pid       // -1=wait for any child process, >0=wait for child with given PID
                ,int* status    // see below
                ,int options    // pass 0 for default options
                );
  • The wait() system call suspends execution of the calling thread until one of its childen terminates
  • The waitpid() system call suspends execution of the calling thread until a child specified by the pid argument has changed state
  • By default, waitpid() waits only for terminated children - similar to wait().
  • The following are state changes:
    • The child terminated
    • The child stopped due to a signal
    • The child was resumed due to a signal
  • In the case of a terminated child, calling wait() or waitpid() allows the system to release resources associated with the child. If wait() or waitpid() is not called, the child remains in a zombie state.
  • If the child has already changed state, the call returns immediately.
  • Otherwise, the call will block until either the child changes status or a signal handler interrupts the call.
  • If status is not NULL, waitpid() will store status information of the child PID into the integer it points to.
  • The integer can be inspected with the following macros which take the integer (as opposed to the pointer) as input.
  • WIFEXITED(status) - returns true if the child terminated normally (by calling exit(), _exit(), or returned from main()
  • WEXITSTATUS(status) - returns the exit status of the child. This is either the least significant 8 bits of the status argument passed to exit(), _exit() or the argument of return statement from main(). This macro should only be called if WIFEXITED returned true.
  • WIFSIGNALED(status) - returns true if the child process was terminated by a signal
  • WTERMSIG(status) - returns the signal number which terminated the process. This macro should only be called if WIFSIGNALED returned true.
  • WIFSTOPPED(status) - returns true if the child process was stopped by delivery of a signal
  • WSTOPSIG(status) - returns the signal number which stopped the process. This macro should only be called if WIFSTOPPED returned true.
  • WICONTINUED(status) - returns true if the child process resumed execution due to SIGCONT delivery.
