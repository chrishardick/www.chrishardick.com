Bash: Flow Control

Exit Status

If you're a programmer, you must understand that flow control conditions are based upon exit statuses of commands as opposed to the pure boolean (true/false) logic that you're used to. The condition that you specify is not actually a condition at all; it's actually an expression which evaluates to an exit status. The condition can be a single command or multiple commands seperated by commas-in which case the expression evaluates to the exit status of the last command in the list. In UNIX, an exit status of 0 means that the command completed successfully; while any other exit status denotes an error

return N

The return statement allows you to exit out of the surrounding function with exit status N. N is actually optional, it defaults to the exit status of the last command which executed. Functions without a return statement also return the exit status of the last command which executed.

if/elif/else

Syntax

if condition1
then
	statement(s) #normal processing (exit status of 0 from condition1)
[elif condition2
then
	statement(s)] #normal processing (exit status of 0 from condition2)
[else
	statement(s)] #neither condition yielded an exit status of 0 (all else failed)
fi

Logically Combining Exit Statuses - Short Circuit Evaluation

Bash allows you to logically combine exit statuses using && and || (logical and & logical or, respectively). Short Circuit Evaluation is implemented; this means that both conditions are not evaluated if they do not need to be. This deserves an example; let's say you have a logical and and the first condition is false, is there any reason to evaluate the second condition? Likewise, let's say you have a logical or and the first condition is true, is there any reason to evaluate the second condition? 

LOGICAL AND EXAMPLE

if condition1 && condition2
then
	statement(s) #both condition1 and condition2 returned a 0 exit status
else
	#condition1 returned a non-zero exit status (condition2 not exexuted--why?)
	#-or-
	#condition1 returned a zero exit status and condition2 returned a non-zero exit status
	statement(s) 
fi


LOGICAL OR EXAMPLE

if condition1 || condition2
then
	#either condition1 or condition2 returned a 0 exit status
	#if condition1 returned a 0 exit status (condition2 was not executed--why?)
	statement(s) 
else
	statement(s) #condition1 and condition2 returned non-zero exit statuses
fi

Testing Conditions Other Than if a Command Ran Properly

Exit statuses are the only thing an if statement (or any other flow control statement) can test. However, this does not mean that we can't test for other conditions. Bash provides the [ ... ] construct (which is equivalent to the 'test ...' construct along with the [[ ... ]] construct to test conditions other than if a command successfully executed. Basically, these constructs return an exit status of 0 when the statment is true and non-zero when false. NOTE: spaces are required after the opening square bracket and before the closing square bracket.

Which one should you use? Basically, test (which is equivalent to [ ... ]) is older and harder to use. [[ ... ]] which originated in ksh is newer and easier to use.

[[ ... ]] test construct

if [[ CONDITION-A || CONDITION-B ]]; then

    #
fi


# e.g.

if [[ ! -e file ]]; then

    echo "File does not exist"
fi

The following operators can be used inside of the [ ... ] or [[ ... ]] constructs:

  • String Comparision Operators
  • File Attribute Checking Operators
  • Integer Condition Operators

String Comparisons

Operator True if...
str1 = str2 str1 is equivalent to str2
str1 != str2 str1 is not equivalent to str2
str1 < str2 str1 is less than str2
str1 > str2 str1 is greater than str2
-n str1 str1 is NOT null (has a length greater than 0)
-z str1 str1 is null (has a length of 0) 
Some Examples:

x=yes
y=no

if [ $x = $y ]; then
	echo "NOT EQUIVALENT"
else
	echo "EQUIVALENT"
fi

would result in the following output:
NOT EQUIVALENT

if [ $x = $y ] || echo "NOT EQUIVALENT"; then
	echo "Inside the if statement"
else
	echo "echo returned a non-zero exit status"
fi

would result in the following output (assuming echo returns a 0 exit status):
NOT EQUIVALENT
Inside the if statement

File Attribute Checking

Operator True if...
-d file file exists and is a directory
-e file file exists
-f file file exists and is a regular file (not a directory or other special type of file)
-r file You have read permission on file
-s file file exists and is not empty (0 bytes)
-w file You have write permission on file
-x file You have execute permission on file; or directory search permission if it's a directory (the ability to cd to the directory)
-O file You own the file
-G file's group ID matches yours (or one of yours, if you have belong to multiple groups)
file1 -nt file2 file1 is newer than file2
file1 -ot file2 file1 is older than file2 
Some Examples:

# Change to $dir only if it's NOT null, it's a directory and you can search it!
# Also shows use of -a inside the [ ... ] construct
if [ -n "$dir" ] && [ \( -d "$dir" \) -a \( -x "$dir" \) ]; then
	cd $dir
fi

# If you can execute the file and it's not a directory, execute it
# Example of ! (logical not) operator; which is not supported under the Bourne shell
# Notice my heavy use of parenthesis--we could have relied on operator precedence 
# -- but I'm unsure of the rules
if [ \( -x "$file" \) -a \( ! \( -d "$file" \)  \) ]; then
	$file 
fi

for loop

The for loop is different from the for loop in traditional programming in that it accepts a list of arguments rather than a start and ending value for a loop index. In order to implement the traditional for loop found in C/C++ or any other traditional high-level language, use the while loop (see below).

Syntax

list is a list of names; if it is omitted, it defaults to "$@" (the command line arguements each enclosed in double quotes and separated by spaces). 

for name [in list]
do
	statements which can use $name
done

Examples

for x in 1 2 3
do
    echo ${x}
done

for x in in {1..10}
do
    echo "${x}"
done

for x in $(cmd-to-run)
do
    echo ${x}
done

while & until

Syntax

# while the statement is true
# useful for traditional for looping
while condition
do
	statements
done

# until the condition is true (in other words while the condition is false)
# very useful when you're looking to validate input (until the user enters correct information)
# equivalent while statment: while ! condition
until condition
do
	statements
done

NOTE: both loops are pre-test (testing occurs prior to entering the loop)

Examples

i=0
last=10

while [ $i -lt $last ];
do
    echo $i

    i=$(($i+1))
done

case

Syntax

case expression in
	pattern1 )
		statements ;;
	pattern2|pattern3 )
		statements ;;
	...
	* )
		statements ;;
esac

The case statement is very similar to the 'switch' statement in C/C++. Except that the expression can be a string (in C/C++, it's limited to an integer type). The patterns can contain wildcards (filename.??? -or- filename.*), you can also specify multiple patterns to be logically or'ed, seperated by a pipe sign (|). Similar to the default statement in C/C++, there's a * pattern which executes only if all other patterns reached up until that point were not matched (the * is usually the last pattern). For those of you who are not familiar with the C/C++ switch statement, the expression is compared against each pattern in the order they're listed. If a match is found, the statments corresponding to the pattern is executed and execution continues after the 'esac'.
