Pthreads & Stdio


  • stdio uses static buffers
  • posix guarantees that stdio is thread safe by locking each FILE object
  • You do not need to worry about this unless (1) you need to guarantee that multiple operations on a FILE object are uninterrupted (atomic) or (2) you want to avoid locking around each call for greater efficiency (getc( ), getchar( ), putc( ), putchar( ))
  • In order to avoid deadlock, stdio specifies the following lock hierarchy: Lock input stream before output stream and unlock in reverse order. I'm not sure about stderr


Locking & Unlocking File Objects

    #include <stdio.h>

void flockfile    (FILE* file);

int  ftrylockfile (FILE* file);

void funlockfile  (FILE* file);


GETC( ), GETCHAR( ), PUTC( ), PUTCHAR( )

    
/**********
 * GET
 * - returns the char (int format)
 **********/

// get from stdin
int getchar_unlocked (void);          

// get from any file stream
int getc_unlocked    (FILE* stream);   // in: file stream to get char from



/**********
 * PUT
 * - accepts the char to put (int format)
 **********/

// put to stdout
int putc_unlocked    (int c,           // in:  char to put
                      FILE* stream);   // in:  file stream

// put to any file stream
int putchar_unlocked (int c);          // in:  char to put
  • normally getchar( ), getc( ), putchar( ), and putc( ) are implemented as macros for performance
  • because stdio must be thread-safe, these functions (or macros) now need to lock/unlock around the FILE object thereby giving up much of the performance
  • therefore, 4 new functions (noted above) were added, which return to the original implementation & therefore return the performance
  • In order to use these new functions, you must manually call flockfile( ) & funlockfile( )
