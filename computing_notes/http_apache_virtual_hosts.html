Apache HTTP Server - Virtual Hosts

  • Running more than one web site on a single machine
  • Virtual hosts can be IP-based (i.e. a different IP address for every web site) or Name-based (multiple names running on a single IP address)

Name-based Virtual Hosts

  • The server relies on the client to report the hostname as part of the HTTP headers
  • DNS simply maps each hostname to the same IP address
  • Eases the demand for IP addresses (which are becoming scarse)
  • When a request arrives, the web server will find the best (most specific) matching <VirtualHost> entry based on the IP address an port used by the request.
  • If there is more than one virtual host containing the best match address and port combination, Apache will then compare the ServerName and ServerAlias directives to the server name present in the request.
  • If ServerName is not present in a name-based virtual hsot, the server will default to a fully qualified doman name (FQDN) derived from the system hostname
  • If no matching ServerName or ServerAlias is found in the set of virtual hosts containing the most specific matching IP address/port, then the 1st listed virtual host that matches will be used.
  • When you add a name-based virual host to an existing server, and the virtual host arguments match preexisting IP and port combinations, requests will not be handled by a virtual host. In this case, it's usually wise to crate a default virutl host with a ServerName matching that of the base server. New domains on the same interface and port, can be added as subsequent (non-default) virtual hosts

Name-based VirualHosts and SSL

  • Apache will allow you to configure multiple name-based SSL virtual hosts, but it will always use the configuration from the 1st listed virtual host (on the selected IP address and port) to set up the encryption layer.
  • This can really only be used when serving multiple hosts within the same domain. E.g. server1.example.com and server2.example.com 
<VirtualHost *:80>
    # 1st virtual host -- the default for port 80
    ServerName www.example.com
    ServerAlias example.com                 # allows for more than one name
    DocumentRoot "/www/example"
</VirtualHost>

<VirtualHost *:80>
    ServerName www.anotherexample.com
    ServerAlias anotherexample.com
    DocumentRoot "/www/anotherexample"
</VirtualHost>
