Polymorphism

  • Polymorphism (the ability to have many forms), is where different objects can share the same external interface and can be used in the same way. Much in the same way that both a tape player, a CD player, and a DVD player all have PLAY buttons.
  • In C++, polymorphism is supported via virtual functions and abstract base classes

I. Virtual Functions

  • New C++ Keyword: virtual
  • More precisely virtual member functions, because they're only useful within classes
  • Even more precisely -- they're only useful within classes which utilize inheritance
  • When utilizing inheritance in C++, methods may be overridden (not to be confused with overloaded)
  • A Method in a base class may be overridden by a method in a derived class by defining the same function (same name and parameter list) in the derived as that in the base class (assuming the derived class has access to the method in the base class)
  • Virtual functions differ from non-virtual functions as to which function (method) gets called (the base class version or the derived class version), when a pointer (or reference) to an object is used to access the method
  • Non-virtual functions have early (compile time) binding
    • When calling a non-virtual function via either a pointer (or a reference) to an object, the type of the pointer determines which function will be called.
  • Virtual functions have late (run-time) binding
    • When calling a virtual function via either a pointer or a reference to an object, the type of the class in which the pointer points to determines which function will be called.
  • use of the keyword virtual is not necessary in derived class definitions (by definition, if you override a virtual function, the function within the derived is also virtual). However, it's recommended that you also specify virtual in the derived class as it can avoid confusion and help you catch potential bugs
  • This is best explained by example: 
    class CRectangle
{
        public:
                virtual void Draw(); 
};

void CRectangle::Draw()
{
        std::cout << "+=============+" << std::endl;
        std::cout << "|  RECTANGLE  |" << std::endl;
        std::cout << "+=============+" << std::endl;
}

class CSquare : public CRectangle
{
        public:
                virtual void Draw();
};

void CSquare::Draw()
{
        std::cout << "+==========+" << std::endl;
        std::cout << "|          |" << std::endl;
        std::cout << "|  SQUARE  |" << std::endl;
        std::cout << "|          |" << std::endl;
        std::cout << "+==========+" << std::endl;
}

int main (int argc, char* argv[])
{
        CRectangle cRect;
        CSquare    cSq;

        CRectangle* cRectPtr[2];

        cRectPtr[0] = &cRect ;
        cRectPtr[1] = &cSq ;

        for (int i=0; i < 2; i++)
        {
                cRectPtr[i]->Draw();
                std::cout << std::endl;
        }

        return 0;
}

+=============+

+==========+
|          |
|  SQUARE  |
|          |

  • Constructors cannot be virtual. It wouldn't make sense - constructors are used to instantiate new objects
  • Destructors should always be virtual. When an object referred to by a pointer or reference is destroyed, the class of the object pointed to (rather than the type of pointer), determines which destructor will be called

II. Abstract Base Classes

  • Abstract base classes are classes which can only be used for deriving other classes. They cannot be instantiated.
  • An abstract base class is a class with a pure virtual function
  • In a class derived from an abstract base class, each pure virtual function must either be defined or re-defined as pure virtual (in which case the class is another abstract base class which cannot be instantiated)
