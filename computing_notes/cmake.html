CMake

In an nutshell...

  • A Makefile generator
  • Useful when the build process becomes complicated - i.e. programs need to built across several platforms, etc.

From the CMake website...

  • An extensible, open-source system that manages the build process in an operating system and compiler independent manner.
  • CMake is designed to be used in conjunction with the native build environment (e.g. make)
  • Simple configuration files placed in each source directory (CMakeLists.txt) are used to generate standard build files (e.g. makefiles in Unix)
  • Use CMake to compile source code, create libraries, build executables, etc.
  • CMake supports in-place and out-of-place builds. Out-of-place builds allow you to use a single source tree to generate multiple builds (e.g. 32 and 64 bit, etc.)

Basic Procedure

  • Create CMake configuration file - CMakeLists.txt - see examples below
  • Execute cmake .
  • Execute make
  • Executable or Libary should be built

Hello, World!

  • Create CMakeLists.txt in your project directory with the following contents: 
    cmake_minimum_required(VERSION 3.0.0)
set (CMAKE_CXX_STANDARD 11)
project (hello_world)
add_executable (hello_world main.cpp)
  • Execute cmake .
  • Execute make
  • Execute ./hello_world

Multiple Source, Standard Include Directory

  • Create CMakeLists.txt in your project directory with the following contents: 
    cmake_minimum_required(VERSION 3.0.0)
set (CMAKE_CXX_STANDARD 11)
project (exec_name)

include_directories(include)
include_directories(../node)

# generate a list of files that matching the globbing expression and store into given variable (SOURCES)
file (GLOB SOURCES "src/*.cpp" "../node/*.cpp")

# add an executable to the project using the specified source files
add_executable (exec_name ${SOURCES})
  • Execute cmake . - must be re-run anytime you need to re-generate your makefiles
  • Execute make
  • Execute ./exec_name

Static Library

  • Create CMakeLists.txt in your project directory with the following contents: 
    cmake_minimum_required(VERSION 3.0.0)
set (CMAKE_CXX_STANDARD 11)
project (lib_name)
set (CMAKE_BUILD_TYPE Release)

include_directories(include)

file (GLOB SOURCES "src/*.cpp")

add_library (lib_name ${SOURCES})
  • Execute cmake . - must be re-run anytime you need to re-generate your makefiles
  • Execute make
  • Execute ./exec_name

Linking With a Static Library

  • Create CMakeLists.txt in your project directory with the following contents: 
    cmake_minimum_required(VERSION 3.0.0)
project (executable_name)

set (PROJECT_LINK_LIBS libch.a)
link_directories (/cmake/lib)

include_directories (~/cmake/lib/include)

add_executable (executable_name main.cpp)
target_link_libraries (executable_name ${PROJECT_LINK_LIBS})
  • Execute cmake . - must be re-run after each change
  • Execute make
  • Execute ./exec_name

Frequently Used CMake Commands

project (project-name))

  • Sets the name of the project.

add_executable (name source1 source2 ...)

  • Used when you're building an executable.
  • Adds an executable target (name) to be built from the source files listed
  • The actual name of the generated executable will be according to the conventions of the native platform (e.g. name.exe)

add_library (name [ STATIC | SHARED | MODULE ] source1 source2 ...)

  • Used when you're building a library.
  • Adds a library target (name) to be built from the source files listed
  • If the type of library (STATIC, SHARED, MODULE) is not specified, the default type is either STATIC or SHARED depending if the value of the BUILD_SHARED_LIBS variable is ON

target_link_libraries (target-name [ PUBLIC | PRIVATE | INTERFACE ] lib1 lib2 ...)

  • Used to specify libraries or flags when linking a given target (executable)
  • If your source files and header fies include the headers of the specified library, then it's a PUBLIC dependency (when in doubt, use PUBLIC)
  • If your source files include the headers of the specified library (but your header files do not), then it's a PRIVATE dependency
  • If your header files include the headers of the specified library (but your source files do not), then it's an INTERFACE dependency

find_package (name [version] [REQUIRED])

  • Find and load settings from an external project
  • The REQUIRED option stops processing with an error message if the package cannot be found

add_subdirectory (source_dir)

  • Add a subdirectory to the build
  • source_dir specifies a directory with a CMakeLists.txt file along with code files

include_directories ([AFTER | BEFORE] [SYSTEM] dir1 dir2 ...)

  • Add the given directories to the list of the directories the compiler uses to search for include files for each target in the current CMakeLists file.
  • By default, the specified directories are appended to the current list of directories. This can be overridden by specifying BEFORE. It can also be overridden via a variable

link_directories (dir1 dir2 ...)

  • Specify the directories in which the linker should search for libraries
  • The command will apply only to targets created after it was called
