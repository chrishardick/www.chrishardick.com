PostgreSQL: libpqxx - C++ Client Library

  • C++ Client Library for PostgreSQL
  • A wrapper around the C Client API - libpq

Include Files

  • #include <pqxx/pqxx>
  • pqxx/pqxx is the standard include file for working with libpqxx

Exceptions

  • The libpqxx library utilizes an inheritance hierarchy for all generated exceptions - which inherit from std::exception 
std::exception
 └── pqxx::failure
      └── pqxx::broken_connection

SIGPIPE

  • Remember, if you're working with Unix (or a Unix-like operating system), you need to ignore SIGPIPE signals 
#include <signal.h>

signal (SIGPIPE, SIG_IGN);  // or similar

pqxx::connection Class

Constructors

  • pqxx::connection::connection (const string& connection_string)
  • Establishes a live session with a PostgreSQL database by initializing and configuring the network connection
  • If there is a problem either establishing a connection or with authentication, a pqxx::broken_connection exception is thrown
  • There is a default constructor which relies on standard PostgreSQL environment variables: PGHOST, PGPORT, PGUSER, and PGPASSWORD
  • There is also a constructor which accepts a std::string_view - see below
  • Once created, the connection stays open until the destructor is called - which cleanly closes the session
  • You cannot execute queries diectly thru the connection object. You need to use a transaction object (e.g. pqxx::work) 
#include <pqxx/pqxx>

try 
{
    // default constructor - uses environment variables
    pqxx::connection conn;

    // constructor which accepts connection string
    pqxx::connection conn("host=127.0.0.1 port=5432 dbname=mydb user=postgres");

    // constructor which accepts std::string_view
    std::string_view conn_str = "postgresql://user:pass@host:port/dbname";
    pqxx::connection conn(conn_str);
}
catch (const pqxx::broken_connection& e)
{
    std::cerr << "Connection Error. Details: " << e.what() << std::endl;
}
catch (const pqxx::failure& e)
{
    std::cerr << "General Pqxx Error. Details: " << e.what() << std::endl;
}
catch (const std::exception& e)
{
    std::cerr << "Exception Occurred. Details: " << e.what() << std::endl;
}

pqxx::work Class

  • The pqxx::work class represents a standard transactional context in the libpqxx library
  • It ensures all database operations executed within its scope are bundled together as a single, atomic unit.
  • Instantiating a pqxx:work object sends a BEGIN command to the database.
  • If any opeation fails, an exception is thrown and the transaction defaults to rolling back.
  • If updates are made, an explicit commit is required. Changes are temporary until you call the commit method.
  • If the object is destroyed before committing, it is automatically rolled back.
  • Provides methods exec() and exec_params()
  • When fetching large datasets, using cursors is usually recommended - see below.

INSERT Example

...

pqxx::work txn{conn};

std::string sql = "INSERT INTO users (name, email) VALUES ($1, $2) RETURN id;"

std::string name = "Chris";
std::string email = "chardick@icloud.com";

pqxx::result res = txn.exec_params(sql, name, email);

if (!res.empty())
{
    int id = res[0][0].as<int>();

    std::cout << "id=" << id << std::endl;
}

txn.commit();

SELECT Example

...

pqxx::work txn{conn};

std::string sql = "SELECT id, name FROM users WHERE status=$1;";

std::string status = "active";

pqxx::result res = txn.exec_params(sql, status);

std::cout << "# RECS=" << res.size() << std::endl;

for (const auto &row : res)
{
    int id = row["id"].as<int>();
    std::string name = row["name"]as<std::string>();
    
    std::cout << "id=" << id << std::endl;
}

if (!res.empty())
{
    int id = res[0][0].as<int>();


}

// optional for pure reads, but good practice
txn.commit();

pqxx::result Class

  • The pqxx::result class is a read-only container object which holds the rows and metadata returned by a PostgreSQL query
  • It is immutable. You cannot modify the data inside a pqxx::result object
  • It contains a copy of the query data. Hence it remains fully readable even if the associated pqxx::work or pqxx::connection object(s) are destroyed.
  • It supports a .size() method which returns the total number of rows contained within the specific query result set. It returns a value of type pqxx::result::size_type which usually maps to a std::size_t
  • pqxx::result mimics a standard C++ STL container. Hence it also supports empty(), clear(), begin(), and end().

Methods

  • .affected_rows() - returns the number of rows modified, inserted or deleted for UPDATE, INSERT and DELETE commands
  • .columns() - returns the total number of columns for each row of the returned dataset
  • .column_name(index) - returns the string name of the column (0 based index)
  • .column_type(index) - returns the PostgrSQL Object Identifier (OID) of the data type of the specified column (0 based index)

pqxx::row and pqxx::field Classes

  • When you loop over a pqxx::result, the iterator yields a const pqxx::row&
  • You can access the individual fields using either a zero-based index number (e.g. row[0]) or the column name (e.g. row["column_name"])
  • Accessing an item inside a row returns a pqxx::field object which can then be converted to a native C++ type 
// extracting a field
pqxx::field id_field = row{"id"};       

// converting it to native c++ type
int id = id_field.as<int>();

pqxx::read_transaction Class

  • You can use pqxx::work without a commit for reads.
  • You can also use the pqxx::read_transaction class - which is optimized for read-only transactions
  • If you execute multiple SELECT statements over a short window, executing them with a single pqxx::read_transaction is much faster than executing them in isolation
  • It allows PostgreSQL to reuse the same snapshot of data and saves on the network overhead of opening and closing the transaction 
void read_recs (pqxx::connction& conn)
{
    try
    {
        pqxx::read_transaction txn{conn};

        pqxx::result rows = txn.exec("SELECT id, name FROM users LIMIT 100");

        if (! rows.empty())
            std::cout << "#ROWS=" << rows.size() << std::endl;

        for (auto row : rows)
        {
            int id = 0;

            // protect against null field values
            if (!row["id").is_null())
                id = row["id"].as<int>()
   
            // alternate method to safely handle null field values
            std::optional<std::string> name = row["name"].as<std::optinal<std::string>>();

            std::cout << "id=" << id << ",name=" << name << std::endl;
        }
    }
    catch (const std::exception& e)
    {
        std::cerr << "ERROR: " << e.what() << std::endl;
    }
}

Cursors

  • Using cursors is advantageous when dealing with large result sets.
  • Cursors tell the PostgreSQL engine to execute the query, but hold the result set on the server
  • The application then issues FETCH instructions to pull a predefined amount (e.g. 5,000 rows) at a time
  • Without using cursors, executing a SELECT query results in all of the rows of the result set being written to the pqxx::result object at once. The application will block until all data is written.
  • When using cursors, the result set is kept on the server until the cursor is closed

pqxx::icusorstream

  • A read-only forward-only cursor
  • Records are read either by using the .read() method or the >> operator

pqxx::icursorstream example

try
{
    pqxx::work txn{conn};

    pqxx::icursorstream stream{txn, "SELECT id, name FROM users", 1000 /* chunk size */}

    pqxx::result chunk;

    while (stream >> chunk)
    {
        // chunk now contains up to 1,000 rows

        for (*const auto& row : chunk)
            // process each row

        std::cout << "finished processing chunk of " << chunk.size() << " rows" << std::endl;
    }
}
catch (const std::exception& e)
{
    std::cerr << "ERROR: " << e.what() << std::endl;
}

pqxx::stateless_cursor

  • C++ Wrapper around a PostgreSQL random access server-side cursor
  • Supports random access. I.e. you can retrieve specific row ranges by index irregardless of where the cursor currently points.

Methods

  • .retrieve(begin_pos, end_pos) - allows you to fetch a small chunk
  • .size() - total number of records

Cursor Name (cname) Notes

  • If the hold parameter is set to false, (standard cursor, which is destroyed when the transaction ends), the cursor name only needs to be unique within that specific open transaction
  • If the hold parameter is set to true, (held cursor, which remains alive even after the transaction ends), cname needs to unique across the entire lifetime of the database connection or until you explicitly close the cursor. If you attempt to create anotehr cursor with the same name, you will receive a naming collision error.
  • You can also pass in an empty string ("") in which case, the library will generate a unique name eliminating the risk of a collission. 
try
{
    pqxx::work txn{conn};

    pqxx::stateless_cursor<pqxx::cursor_base::read_only, pqxx::cursor_base::owned> cursor(
                    txn, 
                    "SELECT id, name FROM users"
                    "select_users_cursor"    // cname (cursor name) - see note above
                    false   // hold = false (close cursor when transaction ends)
                    );

    size_t total_rows = cursor.size();  // total number of rows
    size_t chunk_size = 1000;
    
    for (size_t i = 0; i < total_rows; i += chunk_size)
    {
        size_t end_index = std::min(i + chunk_size, total_rows);

        pqxx::result chunk = cursor.retrieve(i, end_index);;

        for (const auto& row : chunk)
        {
            // process each row
        }

        std::cout << "finished processing rows " << i << " to " << end_index << std::endl;
    }
}
catch (const std::exception& e)
{
    std::cerr << "ERROR: " << e.what() << std::endl;
}

Cursor Example with a Query with Parameters

  • Neither pqxx::icursorstream or pqxx::stateless_cursor support execution of a query with parameters
  • In order to utilize a cursor with a parameterized query, you must explicitly create a cursor using a DECLARE statement
  • You then need to use the FETCH statement to retrieve chunks of records from the database 
try
{
    pqxx::work txn{conn};
  
    std::ostringstream sql_oss;

    sql_oss <<    "DECLARE get_users_cursor CURSOR FOR"
            <<    " SELECT id, name"
            <<    " FROM users"
            <<    " WHERE status=$1"
            ;
   

    // query parameters

    std::string status = "active";

    pqxx::params params;
    
    query_args.append(status);


    std::cout <<  "SQL=|" << sql_oss.str() << << "|"
              <<  " PARAMS=[" << status << "]"
              <<  std::endl;


    // execute query with parameters

    txn.exec_params(sql_oss.str(), params);


    unsigned int batch_size = 1000;

    std::ostringstream fetch_oss;

    fetch_oss << "FETCH " << batch_size << " FROM get_users_cursor";

    pqxx::result res;

    do 
    {
        std::cout << "SQL=| << fetch_oss.str() << "|" << std::endl;

        res = tsn.exec(fetch_oss.str());

        std::cout << "GOT " << res.size() << " RECS" << std::endl;

        }

}
