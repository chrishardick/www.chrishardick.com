Python: subprocess module

  • The subprocess module is most frequently used to execute external commands - capturing their output or return code
  • For basic use cases, use one of the wrapper functions (call() or (check_output())
  • For advanced cases, use the Popen class
  • One reason to use Popen is that (unlike the wrapper functions), it does not block

Execute External Command - Returning the Process Return Code

  • subprocess.call (args, stdin=None, stdout=None, stderr=None, shell=False)
  • The arguments shown above are only the most commonly used ones.
  • The full function signature is the same as that of the Popen constructor 
import subprocess

subprocess.call(args, stdin=None,stdout=None,stderr=None,shell=False)

# e.g.
print subprocess.call(["echo","hello, world!"])

# produces
0

Execute External Command - Returning Its Output as Byte String

  • subprocess.check_output(args, stdin=None,stderr=None,shell=False,universal_newlines=False)
  • The arguments shown above are only the most commonly used ones.
  • If the return code is non-zero, a CalledProcessError exeception is raised. The CalledProcessError has returncode and output attributes which contain the return code and any output, respectively.
  • The full function signature is basically the same as that of the Popen constructor, except that stdout is not permitted since it's used internally. 
import subprocess

subprocess.check_output(args, stdin=None,stderr=None,shell=False,universal_newlines=False)

# e.g.
print subprocess.check_output(["echo","hello, world!"])

# produces
hello, world!

shell

  • If shell is True, the specified command will be executed through a shell.
  • The default shell on Unix is /bin/sh
  • Setting shell=True can be a security risk if used on unsanitized input as it can make a program vulnerable to shell injection

Popen Class

  • Unlike the wrapper functions documented above, Popen does not block.
  • The Popen constructor will launch the subprocess in the background

Each Popen object has the following methods:
  • poll() - check if the child process has terminated. Set and return returncode attribute
  • wait() - wait for the child process to terminate. Set and return returncode attribute. WARNING: this will deadlock when using stdout=PIPE or stderr=PIPE and the child process generates enough output such that it fills up the OS pipe buffer. Usecommunicate() to avoid this.
  • communicate(input=None) - Send input data to stdin. Read data from stdout and stderr, until EOF is reached. Wait for the child process to terminate. communicate() returns a tuple (stdoutdata, stderrdata) or None If you want to send input data, you need to creaete the Popen object with stdin=PIPE. Similarly, if you want to receive output via either stdout or stderr, you need to specify stdout=PIPE and or stderr=PIPE at objecdt creation
  • send_signal(signal) - send the indicated signal to the child process
  • terminate() - on POSIX OS's, this will send SIGTERM signal to the child process
  • kill() - on POSIX OS's, this will send SIGKILL signal to the child process
