Python: venv - Virtual Environments

  • venv is a standard library module used to create virtual environments (isolated, project-specific directories) which contain:
    • their own Python interpreter
    • set of locally installed packages
  • It is built into Python 3.3 and later
  • Benefits:
    • Isolation. E.g. you want to use a different version of a module than the one currently installed on your system.
    • Protection. E.g. you want to install a 3rd party package in which you're not sure is safe
    • Reproducibility. E.g. sharing Python scripts can be frustrating if they require a lot of different modules which may not be installed in a given environment. By using a requirements.txt file - see below, others can easily replicate your exact environment

How to Use - Linux

  1. Create: python3 -m venv venv - where the second venv is the name of the folder to be created
  2. Activate: . venv/bin/activate
  3. Install Project Specific Packages: pip install foo, pip install bar
  4. Execute: python3 ./hello_world.py
  5. Deactivate: deactivate

Best Practives / Source Code Organization

my_project/
├── pyproject.toml      # universal configuration file for Python projects
├── requirements.txt    # dependencies
├── venv/               # Virtual environment folder
└── src/                # source code - smaller projects can include this directly in your package root directory
    └── main.py
  • When using venv, you should place your Python files in your project root directory (small projects) or a dedicated subdirectory (e.g. src) - for larger projects,
  • You should never place your source files inside the venv directory.
  • The venv directory is a managed directory for the Python virtual environment and should contain only the interpreter and installed third-party libraries
  • When committing to version control, always ignore the venv directory - it should always be generated from scratch - most likely using a requirements.txt file - see below

requirements.txt

  • You can create a requirements.txt (usually in the project root directory) - which contains all of the libraries required by your project
  • pip install -r requirements.txt to install the libraries listed in the file
  • pip freeze >requirements.txt - will create a file listing every installed library along with its exact version 
# requirements.txt

# install latest version available
flask

# greater than or equal to 
numby>=1.26.4

# strictly enforced version
pandas==2.2.2

pyproject.toml

  • The modern, universal configuration file for Python projects
  • It replaces older configuration files like setup.py, setup.cfg, requirements.txt, etc.
  • It consolidates everything into a single, standarized file
  • Primary Purposes:
    • Defines Build Requirements
    • Stores Project Metadata
    • Stores Tool Configuration

[build-system]
# no entries

name = "my_projecdt"
version = "0.0.1"
description = "awesome project"
