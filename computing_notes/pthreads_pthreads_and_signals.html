Pthreads & Signals


  • Signals which are associated with a specific execution context (SEGV, BUS, FPE, ILL, PIPE, etc.) are delivered to the thread which caused the signal to be raised. These signals are known as synchronous signals and within multi-threaded environments, they are normally handled by signal dispositions
  • All other signals (those not associated with a specific execution context) are delivered to an arbitrary thread. These signals are known as asynchronous signals because they can occur at any time. Within multi-threaded environments, asynchronous signals are normally handled synchronously by calling sigwait ( )
  • See also UNIX Signals -- discusses UNIX Signals (not in the realm of threads)


I. SIGNAL ACTIONS (DISPOSITIONS)

  • Every signal has an associated action (disposition)
  • Signal dispositions are process wide. I.e. a signal disposition is shared between all threads
  • Within multi-threaded programs, signal dispositions are normally only used for synchronous signals (SEGV, BUS, FPE, ILL, PIPE, etc.); while Asynchronous signals are normally handled synchronously by calling sigwait ( )
  • sigaction( ) - POSIX function to set/examine a signal's disposition (associated action)
  • A program must coordinate any use of sigaction() across threads.
  • Because dispositions are process wide (and usually process specific - i.e. different processes want to process signals differently), changing signal dispositions should solely be the job of the main program. Library code should never change signal dispositions.
  • An example: 
    -------------------------------------+----------------------
thread 1                             | thread 2
-------------------------------------+----------------------
/*                                   |
 * set SEGV disposition              |
 * - process-wide                    |
 */                                  |
 sigaction(SIGSEGV)                  |
                                     |
                                     | /*
                                     |  * set SEGV disposition
                                     |  * - process-wide
                                     |  * - overrides disposition set by thread 1
                                     |  */
                                     | sigaction(SIGSEGV)
                                     |
***SIGSEGV GENERATED***              |
- it will be handled by the          |     
  disposition set by thread 1        |
  (within the context of thread 2)   |


SIGNAL MASKS

  • in a threaded process, each thread has it's own private signal mask
  • signal masks are per thread
  • signal mask: set of signals currently being blocked
  • blocked signals are not delivered (they will remain pending)
  • @ most 1 of each signal type can be pending @ one time (i.e. pending signals are not queued past a depth of 1)
  • sigprocmask( ) - POSIX function to set/examine the process signal mask is NOT supported within a threaded process
  • POSIX introduces a new function - pthread_sigmask ( )
  • when a thread is created, it inherits the signal mask of the thread that created it
  • if you want a signal masked everywhere, mask it in the main thread prior to creating any threads 
    /*
 * SET/EXAMINE THE CALLING THREAD'S SIGNAL MASK
 * 
 * how
 * ===
 * - SIG_BLOCK   = add the signals in 'set' to the calling thread's signal mask
 * - SIG_UNBLOCK = remove the signals in 'set' from the calling thread's signal mask
 * - SIG_SETMASK = set the calling thread's signal mask from 'set'
 *
 * RETURN
 * ======
 * 0 = success
 * else - see discussion on pthreads and errors
 */
int pthread_sigmask (int how,                // in:  SIG_BLOCK|SIG_SETMASK|SIG_UNBLOCK
                     const sigset_t* set,    // in:  signal set (pass NulL to get current signal mask, 'how' is not looked at)
                     sigset_t* oset);        // out: old signal set (pass NulL if n/a)


PTHREAD_KILL( )

  • allows a thread to send a signal to another thread (or itself) within the same process 
    /*
 * SEND SIGNAL FROM ONE THREAD TO ANOTHER THREAD (OR ITSELF) W/I THE SAME PROCESS
 * 
 * RETURN
 * ======
 * 0 = success
 * else - see discussion on pthreads and errors
 */
 */
int pthread_kill (pthread_t thread,    // in:  thread to send signal to
                  int sig);            // in:  signal to send


SIGWAIT( )

  • Recall that signals not associated w/ a specific execution context (asynchronous, because they can occur @ any time) are delivered to an arbitrary thread
  • sigwait( ) allows threaded programs to deal with asynchronous signals synchronously. I.e. a specified thread can wait for asynchronous signals, rather than have them happen @ any time to an arbitrary thread
  • All signals in the given signal set should be masked prior to calling sigwait ( )
  • All signals in the given signal set should not be ignored. This is not normally a consideration because very few signals have a default disposition of 'ignored'
  • sigwait( ) is normally used as follows:
    • in main( ), prior to creating any additional threads, mask (pthread_sigmask( )) the asynchronous signals that you wish to have sigwait( ) thread(s) wait for (they will therefore be blocked in all threads).
    • in sigwait( ) thread(s), call sigwait( ) passing in the signal set that you wish to wait for
    • when a signal arrives, sigwait( ) will return & 'sig' will be set to the generated signal
    • NOTE: if the given signal has a signal handler, it is NOT called 
    /*
 * WAIT FOR SIGNAL IN GIVEN SET
 * - blocking function. it will return when a signal in the given set occurs
 * - will not call a given signal handler
 *
 * RETURN
 * ======
 * 0 = success
 * else - see discussion on pthreads and errors
 */
int sigwait (const sigset_t* set,      // in:  set of signals to wait for
             int* sig)                 // out: signal received
