HTTP - Cookies

Cookies are used for state management for the stateless HTTP protocol. Generally, they're used for:

  • Session Management - login session, shopping cart, etc
  • User preferences - default to menu open, etc.
  • Tracking - track user behavior

WORKFLOW

  • A HTTP cookie is a small amount of data a web server sends to the user's web browser.
  • The browser will then send the cookie back to the web server with all subsequent requests to the same domain
  • It allows for stateful information to be stored in the stateless HTTP protocol.
  • Cookies are transmitted via the HTTP header.
  • Cookies are stored on the client (either in memory, in a file or both -- dependant upon the value of 'expires')
  • See also JavaScript Cookies
  • The Set-Cookie HTTP response header sends cookies from the server to the client
  • The cookie will be sent back on all subsequent applicable requests from the client to the server via the Cookie request header 
        +---------------+                        +---------------+
        | http client   |----------------------->| http server   |
        +---------------+                        +---------------+
                            REQUEST-->
                                
                            GET / HTTP/2.0
                            User-Agent: Mozilla/4.0

                                        <--RESPONSE

                                        HTTP/2.0 200 OK
                                        Content-type: text/html
                                        Set-Cookie: <cookie-name>=<cookie-value>
                                        Set-Cookie: foo-session-id=12345;

                                        ...

                            GET /foo.html HTTP/2.0
                            Cookie: foo-session-id=12345

Cookie Components

Each cookie has the following components

name
value
expires
  • optional. default - transient (it lasts until the user closes the browser)
  • specifing an expiration date, causes the browser to store the cookie in a local file
  • once the expiration date expires, the browser should no longer communicate the cookie to the server, and the file may be deleted
path
  • optional. default - the web page that created it and any other web page in the same directory or subdirectory
  • If you would like your cookie to be accessible to web pages in a higher directory on the same web server (i.e. / for all pages on the web server), you can specify a path (e.g. "/")
domain
  • optional. default - cookie is only accessible only to pages on the same web server
  • If you'd like your cookie to be accessible across multiple web servers (i.e. chris1.chrishardick.com and chris2.chrishardick.com), you can set your domain to .chrishardick.com
secure
  • optional. boolean. default - false
  • If a cookie is marked secure, it will only be transmitted when the browser and server are connected via HTTPS or another secure protocol
