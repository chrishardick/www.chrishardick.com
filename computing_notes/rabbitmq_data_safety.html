RabbitMQ - Data Safety

  • Durable Queues - can survive a broker restart
  • Durable Exchanges - can survive a broker restart
  • Durable Bindings - bindings between durable queues and durable exchanges are durable and therefore can survive a broker restart
  • Persistient Messages
  • Consumer Acknowledgements
  • Publisher Confirms

Consumer Acknowledgements

  • By default, consumers are configured for Manual Consumer Acknowledgements
  • I.e. if a client application consumes a message and crashes prior to acknowledging the message, the broker will detect this and resend the message
  • Positive Acknowledgements (Acks) let RabbitMQ know the message has been successfully delivered and processed. Hence it should be deleted.
  • Negative Acknowledgments (Nacks) and Rejects have requeue parameter. If true, the broker will requeue the message(s). If false, the message will be routed to a Dead Letter Exchange if configured. Otherwise it will discarded.

Automatic Acknowledgements

  • If a client is configured for automatic acknowledgements, messages are considered successfully delivered immediately after it is sent
  • Generally, automatic acknowledgements should be considered unsafe. However, it may be ok for applications in which message loss is acceptable
  • Consumer overload must also be considered as manual acknowledgements also provide flow-control.
