OOP - Object Oriented Programming

Objects are all around us. Let's use your watch as a sample object. It has an external interface (i.e. you can get the current date, set the current date, get the current time, and set the current time). It also a lot of internal stuff that people like you and me don't know about - nor do we care about. After all, we're the user's of watches (not watch engineers - or whatever they call people who make watches). This is encapsulation. Notice the important property of encapsulation--a strong, well-defined interface. How the thing works internally can change six ways from Sunday and we don't care. We have our interface.

Clocks have a lot in common with watches. If you were going to make a clock, wouldn't it be nice not have to re-write everything which is exactly the same with watches again for clocks; we could invent an abstract object called a timepiece which housed everything in which watches and clocks have in common. Therefore when we defined both clocks and watches, we'd only have to define what's different, and if something changed, well, we wouldn't have to re-define it in two places, only in our imaginary place holder the timepiece. This is inheritance. Inheritance allows us not to have to re-invent the wheel when designing similar objects.

Let's talk more about the interface; what if we could enforce that every timepiece had to have at least four things which could be done to it. You can get the current time, set the current time, get the current date, and set the current date. If that was the case, I wouldn't have to know what type of timepiece I was dealing with, a watch, a clock, or whatever. As long as I knew it was a timepiece and that timepieces are guaranteed to have this interface, I could communicate with it. This is polymorphism

  • In OOP, a program running on a computer consists of interacting components called objects.
  • Each object should have a well defined public interface
  • As the program executes, the objects interact by sending messages to each other & receiving replies according to the specified interface
  • An object never needs to know anything about the internal workings of the object(s) with which it interacts; It only needs to know what kinds of messages they will accept & what kinds of replies to expect from them (its interface)
  • Many of the objects that a program will use will have the same structure. A class is a complete description of one kind of object. Objects are instances of a class.
  • In C++, classes are user defined data types which contain (1) data members & (2) function members/operators (member functions or methods).
  • Classes can be defined from scratch or can be created by extending and modifying one or more existing classes. The latter is known as inheritance
  • An object can only be manipulated through its public interface. Its internal structure is completely hidden from the user. Similar to a tape recorder or VCR. This is known as data hiding (also encapsulation or data abstraction)
  • Polymorphism (the ability to have many forms), is where different objects (with very different internal structures) can share the same external interface and can be used in the same way. Much in the same way that both a tape player, a CD player, and a DVD player all have PLAY buttons.
