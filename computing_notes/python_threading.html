Python: threading Module

  • Thread based parallelism
  • See also multiprocessing module - which provides process based parallelism
  • Python (at least CPython - which is the most popular Python implementation) utilizes a GIL - Global Interpreter Lock which means only a single thread can have Python bytecode executing in the interpreter at a time.
  • Hence the threading library is not suitable for CPU intensive algorithms.
  • The threading library is useful for multithreading I/O

Thread Class

  • Represents a separate thread of execution
  • There are two ways to specify the thread start function
  • pass a callable object to the constructor
  • override the run() method in a subclass
  • Once a Thread object is created, the thread of execution is started by invoking the start() method - which invokes the run() method in a separate thread

Lock Class

  • The Lock class supports two basic methods: acquire() and release()
  • acquire() is used to obtain a lock. It will block if the lock is currently locked
  • release() is used to release a lock. It will throw a RuntimeError if called on an unlocked lock

RLock Class

  • Similar to the Lock class. However, it's re-enterant. I.e. can be obtained multiple times by the same thread.
  • In other words, acquire()/release() calls may be nested and only the final release() actually allow another thread blocked in acquire() to proceed

Context Management Protocol - with statement

  • All of the objects which have acquire() and release() methods can be used as Context Managers for a with statement.
  • The acquire() method will be called when a block is entered and the release() method will be called when the block is exited. 
# use of with statement
with some_lock:
    # do something


# equivalent without using with statement
some_lock.acquire()
try:
    # do something
finally:
    some_lock.release()

Condition Class

  • Condition Variable class
  • Condition variables are always associated with a lock
  • Either an associated lock is passed in or one will be created by default.
  • The acquire() method is used to acquire the underlying lock. This method calls the corresponding method on the underlying lock.
  • The wait() method is called once you have obtained a lock. It will releases the lock and block until awoken by another thread which called either notify() or notify_all(). Once woken the thread will have re-acquired the lock
  • The notify() method wakes up one of the threads waiting on the condition variable
  • The notify_all() methods wake up all of the threads waiting on the condition variabe
  • notify() and notify_all() do not release the lock. This means the woken thread(s) will not return until the thread calling notify() or notify_all() releases the lock

Semaphore Class

  • Semaphores manage an internal counter which is decremented by each acquire() call and incremented by each release() call.
  • Semaphores can be used to manage resources with limited capacity

Event Class

  • One thread signals an event and other threads wait for it

Timer Class

  • Timer is a subclass of Thread
  • Timers can be used any time you want an action to take place after a specified amount of time
