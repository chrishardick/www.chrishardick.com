Xcode - URLSession

Declaration

class URLSession : NSObject

Purpose

  • The URLSession and related classes provide an API for downloading data from and uploading data to URL's

Tasks

  • Use a URLSession instance to create one or more URLSessionTask instances
  • URLSession has a singleton shared session which can be used for basic requests
  • The URLSession API is asynchronous. It returns data to your app in one of two ways:
    • By calling a completion handler when a transfer completes or ends with an error

    Swift - Completion Hander

    • A Completion Handler is a closure (self contained block of code that can be passed around)
    • It gets passed to a function as an argument and is called when the function is done (hence completion handler)

    URLSessionTask

    • Within a session, you create tasks
    • There are 4 types of tasks:
      1. Data Tasks
      2. Upload Tasks
      3. Download Tasks
      4. WebSocket Tasks
    • Tasks in a session share a common delegate object

    URL Loading System

    • Within a session, you create tasks 
    func startLoad() 
{
    let url = URL(string: "https://www.example.com/")!

    // trailing closure
    let task = URLSession.shared.dataTask(with: url) { data, response, error in
        if let error = error 
        {
            self.handleClientError(error)
            return
        }

        guard let httpResponse = response as? HTTPURLResponse,
            (200...299).contains(httpResponse.statusCode) else {
            self.handleServerError(response)
            return
        }

        if let mimeType = httpResponse.mimeType, mimeType == "text/html",
            let data = data,
            let string = String(data: data, encoding: .utf8) 
            {
                DispatchQueue.main.async 
                {
                    self.webView.loadHTMLString(string, baseURL: url)
                }
            }
    }
    task.resume()
}
  • You use a URLSession instance to create one or more URLSessionTask instances which can: (1) fetch and return data to you app, (2) download files or (3) upload files to remote locations.
  • Use a URLSessionConfiguration object to configure a session
  • Each session is associated with a delegate which receives periodic updates (and/or errors)
  • The default delegate calls a completion handler block that you provide
  • If you provide your own custom delegate, the competion handler block is not called
  • You can configure a session to run in the background, so that the system can download data on its behalf and wake up the app to deliver the results.
