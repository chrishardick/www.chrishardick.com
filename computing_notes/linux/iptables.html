IP Tables

  • Linux firewall
  • Works via packet filtering
  • More aptly called Iptables/Netfilter
  • Iptables is the userspace module. Netfilter is the kernel module
  • Iptables breaks down into tables which are pre-defined. Each table has chains (both user and pre-defined), and each chain has a rule set which is an ordered set of rules
  • The type of traffic defines which tables and pre-defined chains are consulted. The network traffic (IP packets) are then checked against the appropriate rule sets and a decision is is made as to what action to take with each packet -- which usually breaks down to either DROP or ACCEPT
  • The actions are known as targets.
  • Also provides NAT (Network Address Translation) -- which allows you to modify the source or destination addresses. See below.

USEFUL COMMANDS

  • iptables -L [chain] -nv --line-numbers -Z -- show currently loaded rules for specified chain (or all chains. -n to avoid dns lookups and display ip addresses, -v for verbose which will display byte and packet counts. -Z will atomically display and zero out byte counts
  • iptables -S [chain] -v -- print all rules in the selected chain in iptables-save format. If no chain is selected, all chains are printed. -v for byte counts
  • lsmod | grep ip_tables -- check if iptables module is loaded
  • ismod ip_tables -- if your kernel has iptables support as a module and you need to load it

TABLES

  • Notes on the various tables: filter, nat, mangle and raw
  • Taken more-or-less straight from the Linux man page

1. filter

  • This is the default table (i.e. if the -t option is omitted)
  • Unless otherwise noted, these notes refer to this table
  • It contains 3 built-in chains: INPUT (for packets destined to local sockets), FORWARD (for packets being routed through the box), and OUTPUT (for locally-generated packets).

2. nat

  • This table is for NAT (network address translation -- see below).
  • It is consulted when a packet that creates a new connection is encountered.
  • It contains 3 built-in chains: PREROUTING (for altering packets as soon as they come in), OUTPUT (for altering locally-generated packets before routing), and POSTROUTING (for altering packets as they are about to go out).

3. mangle

  • This table is used for specialized packet alteration.
  • It has five built-in chains: PREROUTING (for altering incoming packets before routing), OUTPUT (for altering locally-generated packets before routing), INPUT (for packets coming into the box itself), FORWARD (for altering packets being routed through the box), and POSTROUTING (for altering packets as they are about to go out).

4. raw

  • This table is used mainly for configuring exemptions from connection tracking in combination with the NOTRACK target.
  • It registers at the netfilter hooks with higher priority and is thus called before ip_conntrack, or any other IP tables.
  • It provides the following built-in chains: PREROUTING (for packets arriving via any network interface) and OUTPUT (for packets generated by local processes)

filter TABLE: BUILT-IN CHAINS

  • By default, the iptable filter table has three built in chains -- which cannot be deleted.
  • INPUT -- all packets destined for our machine.
  • OUTPUT -- all packets orinating from our machine.
  • FORWARD -- all packets being routed by our machine. this chain is used if we are using our machine as a router.
  • Rules are added to each chain in a list. Each packet is checked against the rules of the corresponding chain. If it matches, the corresponding action is taken and no further rules are evaluated.
  • If no rules are matched, the default action for the given chain is taken -- which must be either ACCEPT or DROP

OPTIONS

Options to Manage an Entire Chain

  • -N chain - create a new chain
  • -X chain - delete an empty chain
  • -E old-chain new-chain - rename chain
  • -X chain - delete an empty chain
  • -L [chain] - list the rules for a chain. Useful options are -n, -v, and -x. -n (numeric) causes iptables to print ip addresses rather than making remote calls to DNS which can be slow. It also causes port numbers to be displayed -- rather than a port name. -v (verbose) causes iptables to print out packet and byte counters (by default K, M, and G are used to kilobyte, megabyte and gigabyte -- use -x to display actual numbers).
  • -P chain target - set default policy for given chain. Only pre-defined chains can have default policy and default policies cannot be another chain -- i.e. must be ACCEPT, DROP
  • -F [chain]- flush (remove) rules in the specified chain
  • -Z [chain [rule-number]] - zero packet and byte counters for the specified chain [and rule]. Defaults to all rules of all chains. Use together with -L to atomically report and reset the numbers

Options to Manage Rules of a Chain

  • -A chain rule-specification - append rule to the end of the selected chain
  • -I chain [rule#] rule-specification - insert rule at specified rule number. 1 is the default rule number. i.e. 1st rule in the list (highest priority)
  • -D chain rule# delete rule
  • -R chain rule# rule-specification - replace rule

Options to Manage a Rule -- Selectors & Actions

  • -i [!] in interface - lo (loopback), eth0, ... . An interface name ending with '+' will match all interfaces which begin with that string (e.g. eth+) . (! negates)
  • -o [!] out interface - see comments for in interface
  • -p [!] protocol - ICMP, TCP, UDP. Case insensitive (! negates)
  • -s [!] source IP address[/mask] - source IP address. do not use a name which needs to be looked up via remote call (e.g DNS). mask can either be a network mask (e.g. 255.255.255.0) or a plain number (e.g. 24), where the plain numbe is the number of 1's in the left side of the network mask. Whereby the mask specifies which part of the IP address are significant (! negates)
  • -d [!] destination address[/mask] - destination address. see comments under source IP address.
  • --sport port -- source port
  • --dport port -- destination port
  • -f -- the rule only applies to the 2nd or later fragments. See section on fragments below.
  • -j action -- action: ACCEPT, DROP, another chain name

MODULES

  • Both the kernel and iptables can be extended via modules
  • Kernel modules usually live in /lib/modules/2.XXX/kernel/net/ipv4/netfilter
  • Iptable modules are shared libraries (.so) which usually live in /usr/local/lib/iptables. However, distributions usually put them in /lib/iptables or /usr/lib/iptables
  • Modules come in two flavors: new targets (other than ACCEPT, DROP) and new matches (for example state matching)
  • Use the -m option to load an extension
  • State matching. See example above. The following states are supported: NEW (a packet which creates a new connection), ESTABISHED (a packet which belongs to an existing connection), RELATED (a packet which is related to, but not a part of, an existing connection -- for instance a packet establishing a ftp data connection), INVALID (a packet which could not be identified)
  • Examples of target modules are LOG -- which provides kernel logging of matching packets, and REJECT which is similar to DROP except that the sender receives a ICMP port unreachable error message.

User Defined Chains

  • Iptables (like its predecessor, ipchains), allows you to create user-defined chains.
  • Usually this is done to group related rules together
  • User-defined chains names must be <= 31 characters and by convention are usually lowercase
  • When a packet matches a rule whose target is a user defined chain, the packet traverses the rules of the user defined chain
  • If no rules of the chain match the packet, traversal resumes on the next rule of the current chain.
  • User defined chains can jump to other user defined chains
  • Use -N option to create a new chain
  • Use -X option to delete a chain
  • Use -F option remove all rules from the chain
  • Use -L option to list all rules in a chain. The refcnt for each user defined chain is the number of rules which define this chain as their target. It must be zero before a given chain may be deleted.

FRAGMENTS

  • Sometimes, a packet is too large and it gets split into fragments
  • When this happens, only the initial fragment has the complete header
  • If you are doing NAT or are working with the INPUT chain, then all fragments will be merged into the origial packet before reaching the packet filtering engine

SET UP BASIC FIREWALL

iptables -P INPUT ACCEPT                                                        # input chain -- temporarily allow all connections so we do not lose connection (if necesary)

iptables -F                                                                     # flush rule set -- clear all rules (other than default rules)

iptables -A INPUT -i lo -j ACCEPT                                               # input chain -- append rule (-A) accept all on loopback interface (127.0.0.1)
iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT                # input chain -- append rule (-A) accept all packets on previously established connections
iptables -A INPUT -p tcp --dport 22 -j ACCEPT                                   # input chain -- append rule (-A) allow ssh
iptables -A INPUT -s 192.168.0.0/255.255.255.0 -j ACCEPT                        # input chain -- append rule (-A) allow connections from known ip addresses
iptables -A INPUT -s 192.168.1.1 -m mac --mac-source AA:BB:CC:DD:EE -j ACCEPT   # input chain -- append rule (-A) allow connections from known ip and mac address 
iptables -P INPUT DROP                                                          # input chain -- default policy -- DROP

iptables -P FORWARD DROP                                                        # forward chain -- default policy -- DROP

iptables -P OUTPUT ACCEPT                                                       # output chain -- default policy -- ACCEPT

iptables -L -v                                                                  # list the rules 

service iptables save                                                           # save the rule set such that it's reloaded upon reboot

NAT -- Network Address Translation

What is NAT?

  • Normally packets on a network travel from their source to their destination -- possibily thru a myriad of routers -- not really being altered
  • With NAT, this is not true. NAT alters the source or the destination of the packets
  • NAT comes in two flavors: Source NAT (SNAT) and Destination NAT (DNAT).
  • Source NAT is when you alter the source address of the first packet. It is always done post-routing. Masquerading is an example of SNAT.
  • Destination NAT is when you alter the destination address of the first packet. DNAT is always done pre-routing -- when the packet first comes off the wire. Port forwarding and proxying are examples of DNAT.

NAT -- Main Uses

  • Share your internet connection with other machines that do not have a public IP address. In order to accompish this, you must alter the source address of the packets leaving the local network and the destination address of the packets destinated for the local network. This is commonly known as IP masquerading.
  • Sometimes you have one public internet address, but would like different hosts to handle the traffic destinated for different ports. This is commonly known as port forwarding
  • Proxying. Routing packets which are being routed through the current host are instead routed to a program running on the local host

Quick And Easy Masquerading

# load nat module
modprobe iptables_nat

# NAT table (-t NAT), append rule to chain POSTROUTING (-A) with action masquerade (-j MASQUERADE)
# - you do not need to specify the source address
iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE

# turn on IP forwarding
echo 1 >/proc/sys/net/ipv4/ip_forward
  • Masquerading is actually a specialized case of source NAT (SNAT).
  • The NAT HOWTO states that it should only be used with dynamic ip addresses. I'm not sure if this is true, or that it should only be used with internal ip addresses

NAT Options to Manage a Rule

  • You can specify the source (-s) or destination (-d) IP addresses
  • You can the input (-i) or output (-o) interface to match. However, on the PREROUTING chain, you can only specify the input interface. Similarly, on the POSTROUTING chain, you can only specify the ouptut interface
