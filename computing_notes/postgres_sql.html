Cursors

  • Cursors tell the PostgreSQL engine to execute the query, but hold the result set on the server as opposed to immediately returning all the data immediately back to the caller
  • They are usually used when working with large data sets
  • Cursors are created using the DELARE statement and rows are retrieved using the FETCH statement

DECLARE [ BINARY ] cursor_name [ [ NO ] SCROLL ] CURSOR [ { WITH | WITHOUT } HOLD ] FOR query

  • Create a cursor which can be used to retrieve a small number of rows at a time out of a larger query
  • After the cursor is created, rows are fetched from it using FETCH
  • cursor_name needs to be different from all other acctive cursor names of the session
  • SCROLL specifies that the cursor can be used to retrieve rows in a nonsequential fashion
  • NO SCROLL specifies that the cursor cannot be used to retrieve rows in a nonsequential fashion. The default is to allow scrolling in some cases.
  • Normal cursors return data in text format, the same as a SELECT would produce. The BINARY option specifies that the data should be returned in binary format. This reduces the need to convert from a string to tha actual data type. E.g. If a query returned a value of 1 from an integer column, you would normally receive a string of "1" from a default cursor. With a binary cursor, you would receive a field with the internal representation of an integer (4 byte integer in big-endian byte order
  • Normally, a cursor is destroyed when its transaction ends. If WITH HOLD is specified and the cursor successfully commits, the cursor can continue to be accessed by subsequent transactions in the same session. Held cursors are clsoed with an explicit CLOSE command is executed on it (or the session ends)

FETCH [ direction ] [ FROM | IN ] cursor_name

direction values:

  • NEXT
  • PRIOR
  • FIRST
  • LAST
  • ABSOLUTE count
  • RELATIVE count
  • count
  • ALL
  • FORWARD
  • FORWARD count
  • FORWARD ALL
  • BACKWARD
  • BACKWARD count
  • BACKWARD ALL
  • NEXT, PRIOR, FIRST, LAST fetch a single row after moving the cusor appropriately. If there is no such row, an empty result is returned and the cursor is left positioned
  • count and FORWARD count are equivalent
  • ALL - fetch all remaining rows. Equivalent to FORWARD ALL
