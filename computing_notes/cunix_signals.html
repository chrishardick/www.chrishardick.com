C/UNIX: SIGNALS

I. INTRO

  • Signal: a message sent to a running process
  • The message can be sent:
    • from one process to another process
    • from a process to itself
    • from the operating system to a process
  • Signals are sometimes called software interrupts
  • Signals can be synchronous or asynchronous
  • Synchronous signals are associated with a particular execution context (SEGV, BUS, FPE, ILL, PIPE, etc.).
  • Asynchronous signals can occur at any time
  • Signals are used for many purposes:
    • reporting error conditions (synchronous - occur when the error occurs)
      • memory segment violation (SEGV)
      • floating point error (FPE)
      • illegal instuction (ILL)
      • bus error (BUS)
      • etc...
    • job control (asynchronous - can occur @ any time)
      • abort (ABRT)
      • stop (STP)
      • continue (CONT)
      • hangup (HUP)
      • terminate (TERM)
      • kill (KILL)
    • communication between process(es) (asynchronous - can occur @ any time)
      • user defined signals (USR1,USR2)
    • enforce time out on lengthly operations
      • alarm (ALRM)
    • etc...
  • Every signal has a disposition (associated action).
  • Every signal starts out w/ a default disposition which (depending on the signal), may or may not be overridden
  • The POSIX method to change a signal's disposition is to call sigaction( )
  • There are three ways in which you can change a signal's disposition:
    • catch the signal. I.e. provide a signal handler (function that will be called when the signal arrives). There are two signals which cannot be caught (KILL & STOP)
    • ignore the signal. There are two signals which cannot be ignored (KILL & STOP)
    • restore the default disposition of the signal. The default disposition is usually to terminate the process. Some signals will also generate a core file (a file named 'core' in the working directory) - which is useful for debugging. Some signals's default disposition is to be ignored (CHLD & URG)
  • IMPORTANT NOTE: when writing signal handlers, it's important to call only re-enterant functions because signal handler execution may be interleaved with main program execution
  • See also PTHREADS and Signals


II. SIGNAL( )

  • ANSI C mechanism to change a signal's disposition
  • DEPRICATED in favor of POSIX SIGNALS, which is more portable & eliminates the short window in which a signal is not handled (see below) 
    #include <signal.h>

/*
 * signal handler function def'n
 * - accepts an int (input signal # - useful when you have 1 fxn that handles multiple signals) and returns nothing
 */
typedef void (*sighandler_t) (int);

/*
 * change a signal's disposition (ANSI C)
 * - the handler will be used to catch ONLY the next signal of the given signal type
 * - after handling the next signal (of the given type), the signal action is restored to the default
 * - if you wish to maintain your signal handler, you must call re-register it by calling signal() again
 * - this leads to a short window in which the signal is not correctly handled 
 *   (i.e. from the time the signal is caught, to the time you re-register your signal handler)
 *  
 * NOTES
 * =====
 * - portablility issues (on some systems, the default signal action is not restored & your signal handler remains)
 * - dangerous due to short window of signal not being correctly handled
 * 
 * RETURN
 * ======
 * - previous signal disposition
 * - previous handler -OR-
 * - SIG_IGN (signal was ignored) -OR- 
 * - SIG_DFL (signal had default disposition)   
 */
sighandler_t signal (   int signum,              // in: signal number (to change the disposition of)
                        sighandler_t handler);   // in: new signal disposition (new signal handler, SIG_IGN or SIG_DFL)


/*
 * An example...
 */ 

static void handle_term (int signal);   /** Fxn to Handle TERM Signals **/


// In main...

/*
 * the next time the process receives a SIGTERM signal, call handle_term()
 */
signal(SIGTERM,handle_term);


III. KILL( )

  • send a signal to a given process 
    #include <sys/types.h>
#include <signal.h>

/*
 * send a signal to a given process
 * 
 * RETURN
 * ======
 * 0 = success
 * -1 = check errno
 */

int kill (pid_t pid,    // in: pid to send signal to
          int sig);     // in: signal to send


IV. ALARM( )

  • send a ALRM signal to your own process in X seconds 
    #include <unistd.h>

/*
 * send a ALRM signal to your own PID in X seconds
 * - may be delayed due to scheduling
 * - a process can have only one pending alarm request
 * - calling alarm() while a pending alarm request exists, will cause the alarm to be rescheduled
 * 
 * RETURN
 * ======
 * # seconds left before outstanding alarm would have been sent (usually 0)
 * -1 if error
 */

unsigned int alarm (unsigned int sec);


V. PAUSE( )

  • pause() sleep until a signal is received. 
    #include <unistd.h>

int pause(void);

/*
 * An Example
 */
while (1)
{
	/*
	 * pause () ->
	 * Sleep Until We Receive a Signal  
	 * & Then Execution Continues as Normal...
	 * But since we're in an infinite loop,
	 * all we'll do from this point on, is process signals!!!
	 */

	pause ();  
}


VI. POSIX SIGNALS

  • more portable than ANSI C SIGNALS
  • signal disposition is maintained (unlike using ANSI C signal handling facility)
  • eliminates window w/o correct signal disposition
  • supports blocking signals via signal masks
  • blocked signals will not be delivered (will remain pending)
  • @ most 1 of each signal type can be pending @ one time (i.e. pending signals are not queued past a depth of 1)

1. SIGNAL SETS

  • sigset_t 
    #include <signal.h>

/*
 * INITIALIZE signal set to be 
 * - empty
 * - fill (all signals)
 *
 * RETURN
 * ======
 *  0 = success
 * -1 = check errno
 */
int sigemptyset (sigset_t* set);       // out: empty signal set
int sigfillset  (sigset_t* set);       // out: filled signal set (containing all signals)


/*
 * ADD/DELETE a specified signal to given signal set
 *
 * RETURN
 * ======
 *  0 = success
 * -1 = check errno
 */
int sigaddset (sigset_t* set,          // in/out: signal set to add signal to
               int signo);             // in:     signal to add 

int sigdelset (sigset_t* set,          // in/out: signal set to remove signal from
               int signo);             // in:     signal to remove


/*
 * TEST
 * 
 * RETURN
 * ======
 *  1 = is a member
 *  0 = is not a member
 * -1 = check errno 
 */
 int sigismember (sigset_t* set,       // in: signal set to test
                  int signo);          // in: signal to check for

2. PROCESS SIGNAL MASK

  • set of signals currently blocked for the process
  • blocked signals will NOT be delivered (will remain pending)
  • @ most 1 of each signal type can be pending @ one time (i.e. pending signals are not queued past a depth of 1) 
    /*
 * SET/EXAMINE THE PROCESS SIGNAL MASK
 * 
 * how
 * ===
 * - SIG_BLOCK   = add the signals in 'set' to the process signal mask
 * - SIG_UNBLOCK = remove the signals in 'set' from the process signal mask
 * - SIG_SETMASK = set the process signal mask from 'set'
 *
 * RETURN
 * ======
 *  0 = success
 * -1 = check errno - probably an invalid 'how' value
 */
int sigprocmask (int how,              // in:  SIG_BLOCK|SIG_SETMASK|SIG_UNBLOCK
                 const sigset_t* set,  // in:  signal set (pass NULL to get current process signal mask, 'how' is not looked at)
                 sigset_t* oset);      // out: old signal set (pass NULL if n/a)

3. SIGPENDING( ) - GET SET OF PENDING SIGNALS

    /*
 * GET SET OF PENDING SIGNALS
 * 
 * RETURN
 * ======
 *  0 = success
 * -1 = check errno
 */
int sigpending (sigset_t* set);        // out: set of pending signals

4. SIGSUSPEND( ) - WAIT FOR SIGNAL

    /*
 * SUSPEND PROGRAM UNTIL THE DELIVERY OF A SIGNAL
 * - a more general form of pause()
 * - replaces the process signal mask w/ the given signal mask and then suspends execution (process goes to sleep) & waits for a signal
 *
 * RETURN
 * ======
 * if the signal handler terminates the program, sigsuspend() will never return
 * else return = -1 w/ errno set to EINTR (received signal doesn't terminate the program)
 * 
 */
int sigsuspend (const sigset_t* sigmask)

5. SIGACTION( ) - CHANGE/EXAMINE SIGNAL DISPOSITION

  • struct sigaction 
    #include <signal.h>

/*
 * struct sigaction
 * - minumum members
 */
struct sigaction
{
     /*
      * signal handler, SIG_DFL, or SIG_IGN
      */
     void (*) (int) sa_handler;

     /*
      * set of signals to be added to the process signal mask during execution of the signal handler
      * - i.e. will be blocked (not delivered to process)
      * - todo: verify that these are added to the process signal mask and do not replace the signal mask
      *   during execution of the signal handler
      * - by default, the signal which triggered the handler will be blocked
      *   (unless SA_NODEFER is specified)
      */
     sigset_t* sa_mask;                          

     /*
      * bitmap of flags
      * - SA_NOCLDSTOP => don't generate SIGCHLD when child processes terminate (I've never seen this used)
      * - SA_RESETHAND => reset signal action to SIG_DFL on receipt (ANSI C Signal Behavior)
      * - SA_RESTART   => restart interrupted system calls rather than returning w/ errno = EINTR
      * - SA_NODEFER   => normally, while a signal is being processed, it's added to the process signal mask
      *                     setting this flag will cause the caught signal NOT to be added to the process signal mask
      */
     int sa_flags;
};
  • sigaction ( ) 
    /*
 * CHANGE/EXAMINE SIGNAL DISPOSITION
 *
 * RETURN
 * ======
 *  0 = success
 * -1 = error (check errno)
 */
int sigaction (int sig,                          // in:  signal
               const struct sigaction* act       // in:  signal action (pass NULL to get current signal action)
               struct sigaction* oact);          // out: previous signal action (pass NULL if N/A)



/*
 * An example...
 */

/* signal handler prototypes */
static void handle_term (int signal);


/*
 * program logic
 */
struct sigaction act;

act.sa_handler = handle_term;

sigemptyset(&act.sa_mask);

act.sa_flags = 0;

sigaction (SIGINT,      // in:  signal
           &act,        // in:  signal action struct
           NULL);       // out: previous signal action struct (n/a)


VII. SENDING SIGNALS FROM THE SHELL

kill [-<signalname>] <pid>

- Send Signal to indicated PID
- Default Signal is SIGTERM
- kill -ALRM 528

killall [-<signalname>] <cmd>

- Send Signal to all processes running a specific command
- Default Signal is SIGTERM
- killall -HUP kermit
