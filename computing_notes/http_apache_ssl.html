Terms

X.509
A standard defining the format for public key certificates.
The public keys can either be signed by a certificate authority (CA) or they can be self signed.
X.509 also defines a certification path validation algorithm which allows certificates to be signed by intermediate CA certificates
X.509 also defines certificate revocation lists which are a means to distribute information about certificates which have been deemed invalid by a signing authority
PEM
PEM (Privacy Enhanced Mail) which was a failed format for secure e-mail
Never-the-less, it's used for certificates
Both private key files (.key) and certificate files (.crt) are in this format
Sometimes utilizes a .pem extension

SSL/TLS Handshake

  • Client: Hello (Cipher Suite, Client Random)
  • Server: Hello (Certificate)
  • Client: Authentication and Pre-Master Secret
    • Client authenticates the server certificate
    • Client creates a pre-master secret for the session, encrypts it with the server's public key and sends it to the server
  • Server: Decryption and Master Secret
    • Server uses its private key to decrypt the pre-master secret
    • Client and Server generate master secret with agreed cipher
  • Encryption and Session Key

Generating A Self Signed Certificate

#
# -nodes 
#   private key will not be encrypted
#
# -newkey rsa:2048
#   creates a new certificate request and a new private key
#   rsa:nbits - generates a RSA key nbits in size
#
# -keyout 
#   private key file to be generated (yourdomain.key)
#
# -out filename
#   certificate file to be generated (yourdomain.crt)
#
openssl req -x509 -nodes -days 365 -newkey rsa:2048 -keyout yourdomain.key -out yourdomain.crt

Generating a Certificate Signing Request (CSR)

  • A CSR is an encoded block of text (using ASN.1 - according to the PKCS #10 specication) given to a Certificate Authority (CA) when applying for a SSL Certificate
  • It is generated on the server where the certificate will be installed and contains information to be included in the certificate (organization name, domain name, etc. - see below). It also contains the public key which will be included in the certificate.
  • A private key is also generated at the same time.
  • A CA will use the CR to create your SSL Certificate.
  • A certificate will only work with the private key that is was generated with. 
#
# req 
#   the command we're executing (certificate creation request in PKCS#10 format) 
#
# -new
#   new certificate request
#   you will be prompted for relevant field values
#
# -newkey rsa:2048
#   creates a new certificate request and a new private key
#   rsa:nbits - generates a RSA key nbits in size
#
# -nodes
#   private key will not be encrypted
#
# -keyout 
#   private key file to be generated (yourdomain.key)
#
# -out filename
#   certificate signing rqeuest file to be generated (yourdomain.csr)
# 
openssl req -new -newkey rsa:2048 -nodes -keyout yourdomain.key -out yourdomain.csr

Installing a Certificate

SSLEngine on

# Server's Certicate
SSLCertificateFile      /etc/ssl/crt/yourdomain.csr

# Server's Private Key
SSLCertificateKeyFile   /etc/ssl/crt/yourdomain.key

Config File Settings

SSLCertificateFile

  • Server's X.509 Certificate File (PEM-encoded)
  • An X.509 certificate contains a public key and an identity - hostname, organization or individual). It is either signed by a certificate authority (CA) or it is self-signed
  • File with certificate data in PEM format 
SSLCertificateFile "/usr/local/apache2/conf/ssl.crt/server.crt"

SSLCertificateKeyFile

  • Server PEM-encoded private key file
  • If the private key is encrypted, the pass phrase dialog is forced at startup time 
SSLCertificateKeyFile "/usr/local/apache2/conf/ssl.key/server.key"

SSLCACertificatePath

  • Client Side Certificates
  • Directory where you keep the Certificates of Certification Authorities (CA's) whose clients you deal with
  • These are used to verify client certificates on Client Authentication 
SSLCACertificatePath "/usr/local/apache2/conf/ssl.crt/"

SSLCACertificateFile

  • Client Side Certificates
  • All-in-one file where you can assemble the Certificates of Certication Authorities (CA's) whose clients you deal with.
  • Concatenation of the various PEM-encoded Certicate files, in order of preference.

Client Side Certificates

  • Server - Generate a root CA key and certificate. The CA is used for signing the client's public key 
    #
# -x509     
#   outputs a self signed certificate instead of a certificate request.
#
# -new
#   new certificate request
#
# -nodes    
#   do not encrypt private key
#
# -key
#   file containing private key
#
# -days
#   number of days to certify the certificate for

  • Client - generates private key and certificate (or certificate request)
