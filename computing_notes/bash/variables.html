Shell Variables

Definition

Variables are named places to store data, usually in the form of character strings. Their value can be obtained by proceeding their name with a dollar sign ($).

Assigning Values to Variables

Assignment is very similar to its analog in traditional programming languages, except that most variables--all that we've seen so far--hold character strings. When assigning values to variables it is important not to have any white space (tabs or spaces) on either side of the equal sign. 

Examples of Assignment of Variables:

x=5
y=20
z=yes
a=$x$y
b=$x$y`date`

Environment (Exported) Variables

Environment or Exported Variables are variables which are passed-by-value to subshells. They are conventionally named using all uppercase.

Example of Exporting a Variable:

x=5
export x

Positional Parameters & Related Shell Variables

Positional Parameters (Command Line Arguments) are passed into a shell script as 1, 2, 3, and so on. There is also positional parameter 0 (zero) which is the name of the shell script as it was invoked (either the absolute path name or a relative path name).

In addition, there are some other shell variables which are related to positional parameters.

  • * is a single string which contains all of the positional parameters seperated by the first character of the IFS (internal field seperator) shell variable.
  • @ evaluates to all of the positional parameters as seperate character strings
  • # evalutes to the number of positional parameters
NOTE: When accessing the values stored in either * or @, surround the variable in double quotes. For example: "$@" or "$*".

Functions & Variables

All variables used within a function have, by default, global scope. This means that after they're assigned a value, the variable can be accessed anywhere. To give a variable local scope, you must physically declare a variable as 'local'. For example: 'local x'. The exception to this rule is Positional Parameters and their associated variables. Functions can accept arguments; they accept arguments in the same way as a script accepts arguments (with the exception of 0 positional paramter 0 is not the function name). In order to accomplish this, positional parameters and their associated arguments are local to the particular function.

Command Substitution

So far, we've seen two ways in which to get a value in a variable: assignment and positional parameters. There is another way: command substitution which allows you to use the standard output of a command as the value of a variable.

The standard Bourne and C Shell Method of Command Substitution is to enclose the command in back ticks (`). This method is also supported in bash. However, bash goes even further by supporting another form of command substitution: '$(UNIX Command)'. The command inside the parentheses is executed and anything the command writes to standard output is returned as the value of the expression. Commands may also be nested; for example: $(ls $(pwd)) -- to list all of the files in the current directory.

Enclosing Variable Names in Curly Brackets

$varname is really shorthand for ${varname}. There are two reasons for the need of the later syntax. The first is so you can reference positional parameters greater than 9. For example: ${10}, ${25}, etc. Otherwise, $10 would produce the value of the 1st positional parameter ($1) followed by a zero (0). The second reason is to clearly deliminate the variable name. For example, let's suppose we want to output the variable CHRIS followed by a _ (underscore). We could use the following command: 'echo $CHRIS_'. However, this would not yield the desired result; it would output the value of the variable CHRIS_. To yield the desired output, we'd have to use the curly bracket variable name notation; e.g. 'echo ${CHRIS}_'. In general, you're safe to omit the curly brackets if the variable name is followed by a character which is NOT a letter, a digit, or an underscore.
