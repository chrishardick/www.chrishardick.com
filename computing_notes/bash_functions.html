Bash: Functions

Syntax

FunctionName ( )
{
    shell commands

    # $1 is the 1st argument
    # $2 is the 2nd argument
    # ...
}

-or-

function FunctionName
{
    shell commands
}

NOTE: 'function' is a keyword in bash.
  • Similar to other scripting languages, a function must be defined before it is used

Function Parameters

  • $1 is the 1st parameter
  • $2 is the 2nd parameter
  • and so on, and so forth

Calling a Function

  • When calling a function, you specify the function name followed by any arguments
  • NOTE: do not enclose the parameters in a parenthesis 
foo ()
{
    echo "$1"
}

# call foo
foo "blah"

Benefits of using Functions

Execution Speed

When you define a function, the function gets loaded into memory for the current shell process, whether this is within a shell script or if you source a script which contains the function at the command line. This allows a function to execute more quickly. Obviously, when the current shell process dies, the function's memory is freed along with the rest of the shell's memory.

Modular Scripts

As any programmer will tell you programs or scripts which are based upon functions, which are reusable chunks of code, are much easier to maintain; not to mention, they're easier to read and understand.

Error Trapping

  • By default, shell scripts continue even when an individual command fails
  • For example, if you have a simple script with 5 commands and the first command fails (returns a non-zero return code) the next 4 commands will be executed regardless 
    cd temp
# insert code here
rm -rf *
  • In the above example, if the first command (cd temp) fails, we will eventually delete all files in the current directory
  • Functions along with the flow control statements we'll learn about later, allow the programmer to create wrappers around standard UNIX commands (or your own programs for that matter), such that if a command fails, your program can display an error message and choose to continue or not continue, depending upon the situation.
