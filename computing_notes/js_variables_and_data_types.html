JavaScript - Variables and Data Types

  • JavaScript (like most scripting languages) is an untyped language.
  • A variable can hold any data type.
  • It's perfectly legal to declare a variable, assign a string to it and subsequently assign a number to it.
  • JavaScript will automatically convert from one type to another as necessary
  • Before you use a variable in JS, it must be declared
  • If you do not explicitly declare a variable, JS will implicitly declare it for you.
  • If you do not specify an initial value for a variable, its value wil be undefined until you initialize it
  • You can also assign a variable to undefined to remove its value 
    //
// undefined
//

var x;
console.assert (x === undefined);

x = "foobar";
console.assert (x != undefined);

x = undefined;
console.assert (x === undefined);
  • Variables are explicitly declared using:
    • var - function or global scope
    • let - block scope
    • const - block scope constant
  • Variables declared globally (outside any function) using var have global scope - they can be accessed from anywhere in the JS program
  • Variables declared locally (inside a function) using var have function scope 
    var i, j, k;            // global scope

function foo ()
{
    var l, m, n;        // function scope

    if (l === undefined)
    {
        console.log ("l is undefined");
    }

    {
        let a=0, b="abc", c=5.2;    // block scope
    }
}
  • JavaScript supports 3 primitive data types:
    • strings
    • numbers
    • booleans
  • JavaScript supports objects
  • In JavaScript, arrays and functions are implemented as objects
  • The core JavaScript language defines numerous pre-defined object classes inclding: Date, RegExp, and Error
  • Some JavaScript types are Reference Types. I.e. the actual variable contains only a pointer (reference) to the actual data. The data is dynamically allocated. Dynamically allocated data which is no longer referenced is cleaned up by the system via Garbage Collection
  • Strings and objects are reference types

Variable Hoisting

  • In JS, variables can be used in a block before they are declared
  • This is because JS implicitly moves declarations to the top of the current script or function
  • NOTE: Variables declared with let or const are not hoisted. 
// hoisting example
function foo ()
{
    x = 5;

    var x;
}

Primitive Data Type Class Wrappers

  • JavaScript predefines class wrappers for each of the primitive data types (numbers, strings, and booleans) named Number, String, and Boolean - respectively
  • The wrapper contains the same primitive data value, but also defined properties and methods that can be used to manipulate the data
  • When you use a primitive type in an object context, JavaScript implicitly creates a wrapper object for the value. The object created is temporary, it's created such that you can access the given property, then it's marked for deletion (such that it can be reclaimed by the system)
  • If you wish to create an non-temporary primitive data type object, you can create one just as you'd create any object 
    var ex = new String("Hello World");
  • NOTE: the reverse is also true, when you use a primitive type object in primitive type context, a temporary primitive type is created

Variable Scope/Lifetime

  • Local variables (defined with var within a function) and function parameters have local scope.
  • let specifies block scope.
  • Local variables take precedence (i.e. hide) global variables of the same name
  • Global variables have file scope. Their scope and lifetime is from point of declaration to the end of the file.

The Global Object

  • When the JavaScript interpreter starts up, before executing any code, it instantiates the Global Object
  • When you declare a global variable, what you're actually doing is defining a property of the Global Object
  • In code which is not contained within a function block, you can use the keyword this to refer to the global object (within functions, this has a different meaning)

The Call Object

  • Local variables (declared within a function) are also properties of an object -- the Call Object
  • When you call a function, you implicitly instantiate a Call Object
