DNS

Basically How it Works...

  • An application (e.g. web browser) tries to connect to a hostname
  • The application sends a request to the operating system (OS)
  • The OS checks /etc/hosts - if the hostname can be resolved, we're done
  • The hostname is sent to the 1st name server listed in /etc/resolv.conf
  • If the name server can resolve the hostname, we're done
  • Otherwise, the name server sends the request to a remote name server
  • There are two types of remote requests, a forward request - usually to the name servers at your ISP or to a public name server (e.g. Google 8.8.8.8 or 8.8.4.4) or a root-name server request. Root servers do not respond with the desired IP address. They respond with the authoritative name server for the given domain.
  • If a root-name server request was made, the name server sends a query to the authoritative name server
  • Name servers cache data for a period of time

The DNS database

  • A distributed, hierarchical, replicated database

FQDN - Fully Qualified Domain Name

A Fully Qualified Domain Name has 3 parts

  • A Top Level Domain Name (TLDN) - such as .com, .net, .edu, etc.
  • The second level domain name - always immediately to the left of the TLDN
  • The hostname - e.g. lithium

DNS Record Types

A Record
The primary name resolver record. Every named host must have an A record which contains the IP address for the host.
CNAME Record
Canonical Name. E.g. an alias for an A Record. It points to a A Record.
MX Record
Mail Server for the domain

DNS Client Configuration

  • Usually this consists of adding the IP addresses of 1-2 name servers to /etc/resolv.conf
  • resolv.conf might be written to at boot time by DHCP or it might have been written to at installation time (for static configuration)
