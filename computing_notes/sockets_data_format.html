Data Format

  • As part of an application layer protocol, data format must be agreed upon
  • I.e. will all data be passed back in forth as character strings -- a common solution which works well providing that both machines utilize the same character set, or will data be passed utilizing an agreed upon binary format
  • Caution should be utilized when passing data in binary format across sockets
  • Different machines have different byte orders (big endian, little endian) which will affect integer types (char, short, int, long)
  • Different machines may also store standard C datatypes with different number of bits (see chart below regarding 32 bit vs. 64 bit machine architectures)
  • If you must pass binary structures (for effeciency, etc.), be sure to explicitly define the data format of each supported datatype (byte order and number of bits)
  • RPC (remote procedure calls) are implemented in this way. The data format utilized is XDR (External Data Representation)
ILP32 vs. LP64
DatatypeILP32 - # bitsLP64 - # bits
char 8 8

ILP32 = standard used w/ most 32-bit architectures: integers, longs, pointers = 32 bits
LP64 = standard used w/ most 64-bit architectures: longs, pointers = 64 bits
